# J10 — Duplicate font IDs silently overwrite registry validation

**Status: PROVEN (2026-10-09)**

## Fix
`scripts/validation/accent-drift.mjs` rejects duplicate `FONT_OPTIONS` ids and duplicate `FONT_STYLESHEETS` keys **before** it builds any Map or object. The diagnosis names both the first and the later stack, and explains the disagreement:
- `FONT_BOOT_DATA` (`Object.fromEntries`) keeps the last entry;
- `applyFontOverride()` (`find`) keeps the first.

Canaries cover the first-versus-last case. `client/src/lib/font-options.ts` was not changed; its six ids are unique.

## Before
Pre-fix gate, /tmp copy:
- A second `inter` with a different valid same-family stack → **0 FAIL** (`evidence-589/j10-before2.log`). It was silently accepted.
- A second `inter` with a DM Sans stack → only an unrelated-looking `font-stylesheet-family` failure (`j10-before.log`), with no duplicate diagnosis.

## Executed proof — mutation probes (/tmp copy)
```

j10-after2.log : FAIL font-duplicate-id :: ... id "inter" twice (first stack "'Inter', system-ui, sans-serif", later "'Inter', ui-sans-serif, sans-serif") ...
```

Real registry: the `accent-drift` registered validation → PASSED (`font-boot-registry :: 6 font option id(s) …`).

## Executed proof — browser
`evidence-589/j08.json`: the picker shows six unique ids and labels:
- system / System default
- inter / Inter
- dm-sans / DM Sans
- source-sans / Source Sans 3
- ibm-plex / IBM Plex Sans
- jetbrains / JetBrains Mono

For every option, after reload the boot state (`data-font`, inline pre-paint) and the runtime state (stored value, checked radio, rendered face) agree. See J08.

## Residue
The /tmp probe copies were deleted.
