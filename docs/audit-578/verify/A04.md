# A04 — Public developer endpoints ignore API keys and advertised premium/standard limits

**Status: FIXED — proven on DEV 2026-10-09 16:07–16:08 UTC (run `__qa_test_plan_580_1791562070462`). Production still runs the
pre-fix code until the next publish (see "before").**

## Fix (server-owned entitlements, no migration needed)
- `server/middleware/apiAuth.ts`: shared key resolution; new `optionalApiKey` — no `Authorization` header = guest; a presented key that
  is unknown, revoked, expired or malformed → `401`. A valid key sets `req.apiKey.tier = "standard"`; the tier is never read from scopes.
- `server/middleware/rateLimit.ts`: removed the unused premium tier and the scope-trusting `dynamicRateLimiter`; new
  `publicApiRateLimiter` — valid key → standard tier, 1,000 req/h, bucket keyed by the key id (`tier:standard` / `apikey:<id>` in the
  shared Postgres store); otherwise free tier, 60 req/h per IP.
- `server/api/public.ts`: all four public routes use `optionalApiKey, publicApiRateLimiter`; `/api/public/me` reports `tier` and `rateLimit`.
- `POST /api/user/api-keys` rejects the reserved tier names `free/standard/premium` (case-insensitive) as scopes with 400.
- `docs/API.md`: premium promises removed; tier table, 401 semantics and rate-limit section match the behaviour.

### Shared-cache partitioning (added after code review, re-run 2026-10-09)
Review finding: the key-aware routes still sent `Cache-Control: public, max-age=60` with no `Vary: Authorization`, so a shared cache
could answer a bad/revoked-key request with a cached 200 and skip the 401 and per-key accounting. Fix: every developer route (see scope section below)
sends `Vary: Authorization` (set before key parsing); valid-key responses are `private, no-store`; API-key 401s are `no-store`;
`/api/public/me` now also runs the standard-tier limiter. Re-run `ONLY=A04 npx tsx docs/audit-578/verify/task580-proofs.ts` → ALL PASS
(log `task580-proofs-A04-cache-output.json`, field `a04Cache`):

| Request (each of resources list, resource detail, categories, tags) | Status | Cache-Control | Vary |
|---|---|---|---|
| anonymous | 200 | `public, max-age=60` | `Authorization, Accept-Encoding` |
| valid key | 200 | `private, no-store` | `Authorization, Accept-Encoding` |
| `Bearer not-a-real-key` | 401 | `no-store` | `Authorization, Accept-Encoding` |
| `/api/public/me` with key | 200, `RateLimit-Limit: 1000` | `private, no-store` | `Authorization` |

`node scripts/validation/http-cache-headers.mjs --spawn --build` (production build) → 32 passed, including the new
"public list Vary: Authorization" and "public bad key 401 no-store" checks.
Limitation: the platform edge in front of production cannot be exercised from the workspace (the dev proxy hostname returns 502 for
`/api/public/*`), so the edge run of "cached 200 then bad key" is part of the post-publish production check.

### Scope of the key policy (second review, re-run 2026-10-09)
Review finding: `GET /api/public/collections/:shareId` (registered with the collection routes) has no key handling, tier limiter or
`Vary`. Decision: it is the read behind the site's shared-collection page, not a developer endpoint, so metering it at 60/h per IP
would break ordinary visitors. The exemption is now explicit in `docs/API.md` (Public API intro + endpoint row) and
`server/http-cache-policy.ts`: the key/tier/cache rules cover the four developer routes plus `/api/public/me`; the shared-collection
read ignores `Authorization` entirely. Proven by `ONLY=A01,A04 npx tsx docs/audit-578/verify/task580-proofs.ts` → ALL PASS
(log `task580-proofs-A01-A04-rerun-output.json`, field `sharedCollectionExemption`): anonymous and `Bearer not-a-real-key` both get
200 with byte-identical 604-byte bodies, `RateLimit-Limit: 600` (the general site API limiter, not the 60/1,000 developer tiers) and
no `Vary: Authorization` (the body does not depend on it). All A04 checks above re-passed in the same run; residue 0.

Documented curl examples (`docs/API.md`): `/api/public/resources?limit=5` 200; `/api/public/resources/185125` 200;
category filter `?category=Encoding%20%26%20Codecs&page=2` 200; `/api/public/me` without a key 401 `Missing Authorization header`.
