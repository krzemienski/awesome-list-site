# D08: Bulk admin handlers accepted invalid IDs and reported false success (VERIFIED)

**Environment.** DEV app (`npm run dev`, workflow "Start application", http://127.0.0.1:5000), restarted after the last server edit on 2026-10-09. Admin calls use the `X-Admin-Audit-Key` header (value comes from the ADMIN_PASSWORD secret, never logged) plus an `Origin` header. Harness sources: `evidence-583/harness/` (`lib.mjs` wraps fetch and psql and records every request, status, response excerpt and SQL result). Fixtures all start with `__qa_test_plan_583_`, are deleted by exact id, and each run ends with this residue query:

```sql
select (select count(*) from resources where title like '__qa_test_plan_583_%' or url like '%__qa_test_plan_583_%') as resources,
       (select count(*) from categories where name like '__qa_test_plan_583_%') as categories,
       (select count(*) from subcategories where name like '__qa_test_plan_583_%') as subcategories,
       (select count(*) from sub_subcategories where name like '__qa_test_plan_583_%') as sub_subcategories,
       (select count(*) from resource_edits e where not exists (select 1 from resources r where r.id = e.resource_id)) as orphan_edits;
```

## Before
Audit SEC-09: bulk approve and delete with `ids:[-1,1e100]` returned **200** with `succeeded:0, failed:2`. The handlers parseInt-coerced their input.

## Fix
- `bulkResourceIdsSchema`: a non-empty (≤1000), unique array of positive int4 JSON numbers. Strings, fractions, negatives, >int4 and duplicates return 400 before any processing.
- Responses are honest: 200 when all succeed, **207** for partial success, **409** when all fail. Each response has a `failures[{id,reason}]` list and a message naming the first failure.
- The admin UI toast reports failures instead of "Successfully …".
