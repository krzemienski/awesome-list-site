# I06 — Blocked and token-only screens: per-screen, per-system design evidence

**Status: PROVEN (reduced matrix), 7 cells honestly UNVERIFIED** (2026-10-09, DEV :5000)

## Before
`tests/parity/runner.mjs` marked every token-only row UNVERIFIED without capturing or auditing it. No per-system evidence existed for the 10 blocked + 25 token-only screens.

## Fix
- `tests/parity/nonpixel-runner.mjs` — a separate non-pixel evidence runner keyed to the 35 screen/state ids in `tests/parity/inventory.json` (no reference page is mounted; `wholeScreenPixelParity: "unavailable"` is written into every results file).
  - Signs in an owned disposable QA admin (Clerk backend-minted, `__qa_test_` prefix, torn down Clerk-first), writes the cell's system/accent to that user's server preferences, and fails closed if `/api/auth/user` is not that identity.
  - Asserts `data-system`/`data-accent` + resolved registry tokens before and after settle (`assertCaptureTheme`).
  - Waits for `document.fonts.ready` + 2 rAF, reveals collapsed `aria-expanded` disclosures **and closed native `<details>`** (never popups/tabs), then runs all six stage-6 component-hook collectors (buttons, inputs, chips, cards, h1s, eyebrows), records computed ink / surface alpha / radius / border / font family+weight / shadow and rest/hover/focus states of real controls, checks page overflow and target size, and runs axe.
  - Transient states use real network transitions (offline/slow via CDP) with an observed ready selector; a state that cannot be reached for real is recorded UNVERIFIED with the reason.
  - Full-page JPEG per cell, kept as review evidence, **not** a baseline.
- Methodology fixes made while triaging (each is a real false positive, not a gate weakening): measure at `scrollTo(0,0)`; `checkVisibility()` filters controls and target rects (a closed `<details>` body still reports layout rects → phantom overlap between the subsubcategory title link and a hidden facet button); resume retries FAIL rows and replaces them by key.
