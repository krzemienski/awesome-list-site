# J09 — Protected-route return coverage relies on manual subset

**Status: PROVEN (2026-10-09, DEV :5000, real Clerk sign-in)**

## Fix
- `scripts/validation/auth-return-audit.mjs` builds a **guard inventory from the source** before any browser run:
  - every client route wrapped in `AuthGuard`/`AdminGuard` in `client/src/App.tsx`;
  - every server document guard regex in `server/routes/non-api.ts`.
- Each inventoried route must have an audited `DEEP_PAGE_ROUTES` entry, otherwise the gate fails and names the route. The guest `/bookmarks` exception is kept: it is a local-state guest route reached through the sign-in action.
- `client/src/components/auth/AuthGuard.tsx` now carries `location.hash` in `redirect_url`.
- **Limitation:** hash fragments are never sent to the server, so routes that the server guard redirects before React boots (`/admin`, `/profile`, …) cannot keep a `#fragment`. The browser never transmits it. Query strings are kept on both paths.

## Before
The deep-return list was hard-coded (profile, admin-resources, contributions, bookmarks, notifications, onboarding), and nothing tied it to the guards. A new protected route went untested silently.
