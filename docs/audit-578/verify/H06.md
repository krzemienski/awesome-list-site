# H06 — Resource API failures presented as removed resources or empty related results

**Status: FIXED and proven on DEV (2026-10-09).**

## Before
- Every non-2xx detail response threw a plain `Error('Resource not found')`, which rendered "removed" copy with no Retry.
- The related query treated loading and error as `[]`, which showed "No related resources yet".

## Fix
- ResourceDetail uses status-aware `ApiError` requests:
  - 404 shows Resource Not Found;
  - 429/5xx shows "Resource temporarily unavailable" with Retry;
  - no network shows the offline state, with Retry, which recovers after reconnect.
- Related resources have separate loading, error-with-Retry and empty states.
- SEO is not demoted: the unavailable state keeps the resource's real title and its index robots.
- **Extra fix, needed for this proof:** `client/src/components/layout/new/ResourceBreadcrumbAncestorDisclosure.tsx` shares ResourceDetail's query key but had a queryFn that threw a plain Error. When it won the race, the 503 path still showed "removed" copy. It now uses `apiRequest`, so the shared cache entry always carries an ApiError with a status. The failing run before this fix is kept as `evidence-587/h06-out.before-breadcrumb-fix.txt`.

## Recipe executed
Script: `evidence-587/h06.mjs` → `h06-out.txt`. Signed out, real Chromium, at editorial 1440 and brutalist 390. The fault is injected with Playwright routing in the test browser only; the server is untouched.
1. Force a 503 on `/api/resources/184739` for every attempt. Result: h1 "Resource temporarily unavailable", alert "We couldn't load this resource. Please try again.", `removedCopy: false`, title "MPEG Standards Documentation — Awesome Video", robots index.
2. Remove the fault and click Retry. The real resource renders.
3. Force a 500 on `/api/resources/184739/related`. The page renders, a related error with Retry shows, and `emptyClaim: false`. After restoring and retrying, 5 related cards appear.
4. Go offline (`context.setOffline(true)`) and navigate to `/resource/185020`. The offline state appears: "You're offline … It will load on its own when you reconnect." Go back online, wait 500 ms, and click the offline Retry if it is still visible. The page loads h1 "100ms: RTMP vs WebRTC vs HLS…" at `/resource/185020` (the script does not record whether the auto-reload or the click did it).
5. A real missing id, `/resource/99999999`, gives document 404, h1 "Resource Not Found" and 0 Retry buttons.
