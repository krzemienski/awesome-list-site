# G01 — Discovery moderation is atomic and idempotent

**Status: PROVEN (2026-10-09, scratch DB)**

## Fix (reviewed + kept)
`server/ai/researchService.ts` — `approveDiscovery` / `rejectDiscovery` run in one transaction that
`SELECT … FOR UPDATE`s the discovery row and only transitions `pending_review → approved|rejected`.
Job counters (`approved_discoveries` / `rejected_discoveries`) are incremented in the same transaction
only when the transition actually happens.
- Repeat reject of an already-rejected discovery → idempotent 200, no counter change.
- Any cross-decision (approve a rejected one, reject an approved one) → **409 "Discovery has already been moderated"**.
- Missing discovery → 404.

## Executed proof (excerpts from `evidence-586/g01_g04.out`)
Fixtures: job 55 (`__qa_test_plan_586…`), discoveries 87 and 88. Counters before: `approved=0 rejected=0`.

```
$ curl -X POST /api/researcher/discoveries/87/reject -d '{"reason":"__qa_test_plan_586 first"}'   -> HTTP 200
$ curl -X POST /api/researcher/discoveries/87/reject -d '{"reason":"__qa_test_plan_586 repeat"}'  -> HTTP 200
job counters after 2 rejects: approved=0 rejected=1
d1 status=rejected reason=__qa_test_plan_586 first          # first reason preserved

$ curl -X POST /api/researcher/discoveries/87/approve
{"message":"Discovery has already been moderated"}  -> HTTP 409
resources with d1 url: 0
d1 status=rejected created_resource_id=null

$ curl -X POST /api/researcher/discoveries/88/approve        -> HTTP 200  (created resource 188645)
job counters after approve: approved=1 rejected=1
$ curl -X POST /api/researcher/discoveries/88/reject -d '{"reason":"__qa_test_plan_586 flip attempt"}'
{"message":"Discovery has already been moderated"}  -> HTTP 409
$ curl -X POST /api/researcher/discoveries/88/approve
{"message":"Discovery has already been moderated"}  -> HTTP 409
d2 status=approved created_resource_id=188645
resource 188645 status=approved (count with d2 url=1)
job counters final: approved=1 rejected=1

# 4 concurrent rejects of a fresh pending discovery (row lock):
parallel reject 1..4 -> HTTP 200
job rejected counter after 4 parallel rejects of d3: 2 (expected 2)   # 1 -> 2, i.e. exactly +1

$ curl -X POST /api/researcher/discoveries/999999999/reject -d '{}'
{"message":"Discovery not found"}  -> HTTP 404
```
