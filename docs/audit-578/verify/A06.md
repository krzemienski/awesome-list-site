# A06 — OpenAPI omits resource/search filter parameters and advertises unrelated generic ones

**Status: FIXED on DEV (proven 2026-10-09 16:08 UTC). Production spec updates on the next publish.**

## Fix
- `server/contracts/endpointSchemas.ts`: named documentation queries — `ResourcesQuery` (`/api/resources`), `SearchQuery`
  (`/api/search`), listing query with `kind`, `PublicResourcesQuery` (`/api/public/resources`), and an empty query for
  `/api/public/categories`, `/api/public/tags`, `/api/tags`. Enums for `kind`, `sort`, `provider`, `format`, `skillLevel`; bounds and
  aliases (`search` vs `q`, `tag` vs `tags`) described.
- `server/contracts/install.ts`: `setRouteQuerySchema(…, { guard })` separates the documented schema from the runtime guard, so the
  handlers keep their own precise errors (`invalid_kind`, `invalid_sort`, case-insensitive facets, repeated `q`).
- `docs/api/openapi.yaml` regenerated; `docs/API.md` gained a "Catalog filters" table + curl examples and still links `/api/openapi.json`
  (lines 7, 168, 410).
