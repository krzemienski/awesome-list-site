# B07 — Step and picker load failures shown as empty data

**Status: FIXED and proven** in a real browser at `/admin/journeys`, desktop 1366px, 402px and 390px, 2026-10-09.

## Before (audit evidence)
Source trace:
- `StepsDialog` ignored the query error and rendered "No steps yet" when GET steps failed.
- `ResourcePicker` rendered "No results" when its search failed.

## Fix
`client/src/components/admin/JourneyStepsManager.tsx` uses the shared `queryUnavailableReason` pattern:
- Steps failure: `role=alert` "Journey steps could not be loaded." (or "You're offline. Reconnect to load journey steps.") with a **Retry** button.
  - "Add step" is disabled until real data has loaded, and the empty state only renders when the steps query actually succeeded.
- Picker failure: `role=alert` "Resources could not be loaded." (offline variant too) with **Retry** instead of "No results.".

## Proof — `browser-admin.mjs b07 <vp>` → `out/browser-admin-b07-{desktop,402,390}.json`
Signed-in throwaway admin (Clerk ticket session), draft QA journey with 3 groups. Failures were injected with Playwright request interception (`page.route` → 503/500), then removed so the retry reaches the real server.
