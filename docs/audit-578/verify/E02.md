# E02: User management and journey edits were missing from the server audit trail

**Status: FIXED, proven on DEV (2026-10-09)**

## Root cause (confirmed)
The user rename, role change and delete routes in `admin-content.ts`, and the journey metadata and step routes in
`journeys-recommendations.ts`, changed privileged data without writing to `resource_audit_log`.

## Fix
- `UserRepository.adminUpdateUserName`, `adminUpdateUserRole` and `deleteUserWithCleanup` now write `user.name_changed`,
  `user.role_changed` and `user.deleted` **inside the same transaction** as the change. Each entry records the
  actor, the target identity (`{type:"user", id, email, label}`) and before/after values. A no-op (same value) returns
  the unchanged row and writes nothing (proven below; this guard was added after code review found the first version
  logged no-ops). Because the target identity lives in `changes.target`, it is preserved after the user row is gone.
- `LearningJourneyRepository` metadata and step methods write `journey.updated`, `journey.step_created`,
  `journey.step_updated`, `journey.step_group_updated`, `journey.steps_reordered`, `journey.step_deleted` and
  `journey.step_group_deleted` transactionally. Each entry has the actor, a `journey:<id>` target and before/after
  step snapshots.
- Failed validations (400) and 404s throw before the write, so no audit row is created for them.
- `AuditTab.tsx` shows the new actions as "completed" with a readable target ("User …", "Journey: …").
- The admin API has no endpoints to create or delete whole journeys. Journeys are created by seeding/AI generation,
  so "journey create/delete" from the recipe maps to step create/delete and group delete, all of which are covered.
