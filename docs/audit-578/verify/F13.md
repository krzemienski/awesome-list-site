# F13 — Partial GitHub imports show Partial, exact counts and every failure (queued and direct)

Status: **FIXED + PROVEN** (scratch DB, disposable private repo, browser + curl)

## Before
Imports with item errors were stored/mapped as `completed`, only a numeric error count was kept and the summary projection dropped metadata (audit OPS-04).
While proving it, two more defects showed up and were fixed: every queued import wrote **two** queue rows (route + service), and the direct
`POST /api/admin/import-github` answered `success:true, "Successfully imported 0 resources"` despite item errors.

## Fix
- Outcome `completed | partial | failed` with all `errorMessages` stored on the queue + canonical history rows; queue/history APIs expose `partial`, `importResult` counts and `errorMessages`.
- Panel: counts line + error list per job, Logs dialog "Failed items (N)", Last Import alert "PARTIAL · N failed".
- Queued route passes `queueRowOwnedByCaller` so the service no longer adds a duplicate queue row.
- Direct endpoint returns `outcome`, `totalErrors`, `success` only when error-free, an honest message, and 422 when nothing landed.
