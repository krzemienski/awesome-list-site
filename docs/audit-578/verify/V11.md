## Limits

- **Received MIME could not be inspected.** The Gmail connector is send-only: reading back the sent message
  returned `403 PERMISSION_DENIED … MailboxService.GetMessage`. What *is* proven: Gmail accepted the message and
  returned a message id; the headers are built in `server/email.ts` `buildMimeMessage()` (`List-Unsubscribe: <url>`
  and `List-Unsubscribe-Post: List-Unsubscribe=One-Click` whenever an unsubscribe URL is passed, which the digest
  path always does). The one-click POST shape is proven in Part A.
- The recipient is a reserved `@example.com` address, so the message bounces; Gmail will place one bounce notice in
  the connected account's inbox. The plaintext unsubscribe link inside that email is therefore not clickable by me;
  the same link format/route was clicked in Part A with an owned token.
- Unsubscribe links in emails point at `PUBLIC_SITE_URL` (production by default). A scratch-DB token sent that way
  is unknown to production and answers 410 there, so no production data can change.
