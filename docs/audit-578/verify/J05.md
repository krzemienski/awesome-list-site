## 2. What changed

- **Server.** Express 4 does not forward a rejected async handler to the error middleware, so the request hangs. Every async route handler that tripped no-misused-promises is now wrapped in `asyncHandler` (`server/middleware/asyncHandler.ts`), and rejections reach the error handler.
  - Floating promises are either awaited or marked `void` with `.catch` logging where they are deliberately fire-and-forget.
  - The timeout helpers now reject with Error objects.
  - Control-character regexes carry per-line justified disables.
  - Files: 30 under server/ and shared/ (see `git diff --stat -- server shared`).
- **Client.**
  - Promise-returning calls in event handlers and effects are now `void`ed (deliberate fire-and-forget; behaviour unchanged).
  - `onClick={async …}` handlers are wrapped as `() => void (async () => …)()`.
  - JSX text like `// Profile` is now a string literal, so it renders the same text.
  - exhaustive-deps: the missing dependency was added in Search.tsx and in ResearcherTab, where `isPolling` converges. In GenericCrudManager, undo/redo keyboard handlers are read through a ref. Six sites keep a per-line disable with a reason, because adding the dependency would change behaviour by re-firing on refetch: useAuth, Bookmarks, Settings, JourneyDetail, and ResourceDetail ×2 (view logging and select_content analytics).
- **eslint.config.js.** Client `react-hooks/exhaustive-deps` raised from warn to **error**.

## 7. Completion-validation follow-up: OpenAPI drift

The first completion run failed `npm run validate:openapi` with "docs/api/openapi.yaml is stale". Cause: wrapping named handlers in `asyncHandler` hid them from route-contract introspection. The generated spec lost each wrapped handler's name and the literal `res.status(201)` codes inside it, so `POST /api/resources` stopped advertising 201, and the `requireApiKey`/`optionalApiKey` middleware names disappeared.

Fix (spec unchanged, no regeneration):
- `asyncHandler` keeps the wrapped function's `name` and exposes it as `wrappedHandler`.
- `explicitResponseStatuses` in `server/contracts/install.ts` reads the inner handler's source.
- The three middleware defined as `asyncHandler(async (…) => …)` (`requireApiKey`, `optionalApiKey`, `clerkUserContext`) became named function expressions.

Re-check after restarting the app:
- `npm run validate:openapi` → "OpenAPI drift PASS: 183 API routes, 183 named contracts, 155 paths".
- `validate:response-contracts` → PASS. `lint:ratchet` → PASS (0 correctness, 6382/6382). `npm run check` → pass.
- curl `/api/public/me`: none → 401 "Missing Authorization header"; bad key → 401 "Invalid API key".
- `/api/public/resources`: bad key → 401; anon → 200.
- `/api/auth/user` anon → 200 `{"user":null,…}`. Admin stats with key → 200. Anon `POST /api/resources` → 401.
