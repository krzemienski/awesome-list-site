# I01 — Violet accent text fails AA on raised surfaces; Magenta on Geist/Brutalist surface-3

**Status: FIXED and PROVEN** (2026-10-09, DEV app on :5000, guest, real Chromium 1223)

## Before
- Static compositing (task audit): Violet failed 34 accent/background pairs (3.4394–4.4592:1); Magenta failed Geist and Brutalist surface-3 over bg-2 (4.4831:1). Small accent text (`.chip.accent` 10.5px, Terminal `.btn.primary` 13px, journey progress labels 12px) painted the raw decorative accent.

## Fix (app-owned; frozen `awesome-list-site-ds*/` and `client/public/ds/*` untouched)
- `client/src/styles/app-bridge.css`: per-system × per-accent `--accent-ink` = the exact accent where it already passes, otherwise the minimal `color-mix(in srgb, <accent> N%, #fff)` that clears 4.5:1 over every neutral backing (bg, bg-2, surface/-2/-3 over both bases) AND the 8%/14% accent tints. Decorative `--accent` is unchanged (borders, rules, swatches, fills).
- 113 small-text accent uses across `client/src/styles/**` and admin CSS switched from `var(--accent)` to `var(--accent-ink)`.
- Gate: `scripts/validation/app-accent-contrast.mjs` (all 50 system/accent pairs × every backing × tints, same compositing calculator the docs use). `canonical-token-parity` lists the override as a documented deviation.
- Artifact projection regenerated (`npm run generate:design-system-artifact` → `tokens.json`, `contrast.json`).
