# G07 — Scraper refuses private destinations on every hop and image

**Status: PROVEN (2026-10-09). SSRF: real scraper code against a real private listener. Safe public enrichment: one real paid job on scratch.**

## Fix (reviewed + kept)
`server/ai/safeFetch.ts` is the shared outbound policy:
- http/https only; URLs with credentials are rejected.
- DNS is resolved and **every** resolved address is checked: loopback, RFC1918, link-local, CGNAT, unspecified, multicast, reserved, IPv4-mapped/NAT64/6to4 IPv6, and decimal/octal encodings.
- The connection is pinned to the checked IP through a custom `lookup`, so DNS rebinding cannot swap it.
- `redirect: "manual"`, with the same check re-run on each hop (max 5).
- One deadline covers headers **and** the streamed body read; a streaming byte cap is enforced.

Callers:
- `server/ai/urlScraper.ts` uses `safeFetch` for the page and for og/twitter images (blurhash).
- `claudeService` / `enrichmentService` go through it.

## Before
`fetchUrlMetadata('http://127.0.0.1:5000/api/version')` reached the loopback server (audit probe).
