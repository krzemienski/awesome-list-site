# B01 — Unpublished journeys leaked to anonymous visitors

**Status: FIXED and proven** on DEV (real app, `npm run dev` on :5000), 2026-10-09.

## Before (audit evidence)
- Anonymous `GET /api/journeys/18` (draft `__qa_test_plan_disc_public_draft`) → **200** with private description and `status:"draft"`, while `/journey/18` HTML → 404.
- Signed-in `POST /api/journeys/22/start` on a draft → **200**, and the draft showed up in `/api/user/continue-learning`.
- Cause: the public detail, start and progress handlers loaded journeys by id with no `status = 'published'` check.

## Fix
- `server/routes/domains/journeys-recommendations.ts`: public detail, `start`, `GET/PUT progress` resolve the journey through a published-only lookup. A draft, archived or missing journey returns the same `404 {"message":"Journey not found"}`.
- Admin routes (`/api/admin/journeys`, `/api/admin/journeys/:id/steps`, `PUT /api/admin/journeys/:id`) keep unrestricted access, so admins can still preview and edit drafts.
- Server HTML (`og-middleware` journey section) already returned 404 for unpublished journeys. It is unchanged apart from the B02 projection.

## Follow-up: publish → enroll → unpublish (code-review finding, 2026-10-09)

**Problem.** A learner enrolls while a journey is published. An admin then unpublishes it and edits the title and description. Before this fix, three user-scoped endpoints still returned the new draft metadata:
- `/api/user/journeys` returned the full journey row.
- `/api/user/continue-learning` returned the title and description even with `isAvailable:false`.
- `/api/user/progress` returned `currentPath`, which was the journey title.

**Fix** (`server/routes/domains/user-features.ts`):
- `/api/user/journeys` sends `journey: null, isAvailable: false` for any journey that is not published.
- continue-learning uses only the generic fallback for unavailable journeys: "Unavailable learning journey", the "no longer available" copy, category `Learning`, difficulty `unknown`, duration `null`. `href` points to `/journeys`.
- `currentPath` names only the first active journey that is still published.
- Progress rows are kept, so the learner's started count and progress fallbacks are unchanged.

**Executed proof.** Script: `task581-harness/unpublish-proof.mjs`. Output: `task581-harness/out/unpublish-proof.txt`. Run against the dev app on :5000 after a restart, with a throwaway Clerk user (non-admin).
