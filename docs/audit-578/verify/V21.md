# V21 — Guest /api/submit forced through the live 429 backstop

**Status: PASS** (no code change needed)
**Run:** 2026-10-10 19:45:31–19:46:35 UTC. Isolated instance E on :5167 against scratch DB `awesome_scratch_592` (a DEV clone). The shared Postgres rate-limit store (`rate_limit_hits`) lives in that scratch DB, so this bucket was used by nobody but this client. The :5000 workflow and any parallel auditors were never throttled.
**Harness:** `task592-harness/v21-submit-429.mjs`. Raw output: `task592-harness/out/v21-submit-429.json`. Not visual, so there are no screenshots.

## Steps
1. Boot E (`DISABLE_BACKGROUND_JOBS=1`), then take SQL counts before the burst.
2. Send a guest, same-origin `POST /api/submit` (`Origin: http://127.0.0.1:5167`, `Accept: application/json`). The invalid body is `{title:"__qa_test_plan_592_v21 invalid", url:"not-a-url", description:"", category:""}`.
3. Repeat in batches of 25 until the first 429.
4. While limited, probe the same bucket with an HTML-accepting client and an unrelated `/api` read.
5. Re-count SQL rows, wait out `Retry-After` + 1 s, then submit again.

## Before/after
Before this run, the 429 path was covered only by code and unit tests (SEC-15). After this run it has been driven over real HTTP: JSON body, `Retry-After`, standard `RateLimit-*` headers, zero writes, and automatic recovery when the window resets.

## Notes
- Guest submissions are rejected by `isAuthenticated` (401) **after** the backstop has counted them, so an unauthenticated flood is still throttled. There is no dedicated signed-in submit limiter, so the "dedicated signed-in limiter" branch of the recipe is not applicable. A user-keyed submit limiter would be a new feature and is out of scope.
- The limiter keys on client IP. On loopback that is `127.0.0.1`, which is why the test had to run on an isolated DB-backed store rather than :5000.

## Residue
`resources LIKE '__qa_test_plan_592%'` = **0**. Instance E was killed by its process group. The scratch DB holds 2 `rate_limit_hits` rows, which go away when `awesome_scratch_592` is dropped.
