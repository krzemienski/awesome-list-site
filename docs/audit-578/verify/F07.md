# F07 — Only one link-health scan can be active

Status: **FIXED + PROVEN** (scratch DB, API, 16:15:42 UTC)

## Before
`linkHealthService.startJob` read active rows, then inserted in a separate query — two concurrent requests could both pass; completion pruned other jobs' checks unconditionally (audit OPS-08).

## Fix
Admission runs in a transaction holding a Postgres advisory lock (check + insert atomic); pruning is scoped to the finalizing job and only when it is still processing.

## Steps / evidence
Catalog reduced to 10 disposable approved `__qa_test_plan_lh_*` resources (rest parked as pending on the scratch DB): 2 → local 200, 1 → 404, others example.com 404.
1. Two concurrent `POST /api/admin/link-health/run`: one `200` (job 1), the other `409 "A link health check is already running"`; SQL active rows = 1.
   Job 1 completed: total 10, healthy 2, broken 8; persisted checks 10 (8 broken); `GET broken-links` → 8.
2. Eight concurrent POSTs: 1 × 200, 7 × 409; active rows = 1. Job 2 completed total 10 / broken 8; checks table contains only job 2's 10 rows after pruning
   → final problem count = persisted checks.
