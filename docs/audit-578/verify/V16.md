## 6. Fix and re-proof (E012)

**Root cause.** `server/ai/promoteEnrichmentSuggestions.ts`:

- It copied the suggested subcategory onto the resource without checking that the node exists under the resource's category.
- It ignored the boolean that `ensureSubSubcategoryExists` returns, so it promoted sub-subcategory labels that could not be placed in the tree.

**Fix.**

- A suggested subcategory is promoted only when that subcategory row exists under the final category. Creating level-1 and level-2 nodes stays admin-driven.
- A suggested sub-subcategory is promoted only when the guard returns `true` (the node existed or was just created under a real chain).
- Suggestions that cannot be placed stay in `metadata` for an admin to act on.
- This one helper serves both the backfill route and live enrichment (`enrichmentService`), so both paths are fixed.
- I updated the unit test that encoded the old "promote as a hint" behaviour. `tests/unit/promote-enrichment-suggestions.test.ts` passes 5 of 5.

**Re-proof** (`v16b-backfill-recheck.mjs`, same scratch DB, restarted instance C):

- Before the fix, P6 as the first run left it: `Sub C1 / Leaf C1x`, `sub_row_exists: false`.
- Fixtures were then reset:
  - P6: Cat C, no subcategory; suggests Sub C1 / Leaf C1x (no Sub C1 row).
  - P3: Cat B, no subcategory; suggests "Sub A1", which exists only under **Cat A**.
  - P2: Cat A > Sub A1, no leaf; suggests a new leaf "Leaf A1 second".

| Run | Response | Effect |
|---|---|---|
| First | 200 "Backfill complete: 1/3 resources updated, 1 sub_subcategories created", `updatedIds:[2]`, `errors:[]` | P2 now has Sub A1 / Leaf A1 second, and the row (id 5 under Sub A1) was created. P3 and P6 are unchanged (null/null). Their suggestions are kept in metadata. |
| Second | 200 "0/2 resources updated, 0 sub_subcategories created" | no-op |

- After both runs, **0** resources carry a subcategory label without a matching row under their category.
- Public `/api/resources/2` shows Sub A1 / Leaf A1 second.
