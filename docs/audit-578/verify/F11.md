# F11 — Export "Run Link Check" is a persistent link-health job with progress, cancel and restart-interrupted state

Status: **FIXED + PROVEN** (scratch DB, background jobs on, browser desktop + mobile)

## Before
`POST /api/admin/check-links` awaited the whole catalog check inside one HTTP request; results lived in process memory only (audit OPS-09).

## Fix
The endpoint starts a persistent link-health job and returns `202 {jobId}` at once; ExportTab polls it (progress, Cancel via the F10 route) and
labels that it checks the stored resource URLs; boot recovery marks interrupted jobs failed.

## Steps / evidence
1. Desktop 16:20:59: /admin/export → Run Link Check → confirm → `POST /api/admin/check-links` 202 job 9; panel "Link check #9 RUNNING … 0 of 40".
2. Navigated to /admin/database (18 s) and back: "10 of 40 links checked" — still observable, progress moved.
3. Cancel link check → `DELETE` 200 → "CANCELLED … Cancelled by administrator".
4. Mobile 16:21:32: started job 10 (RUNNING 0 of 40); 16:21:39 killed the scratch server and restarted it. Boot log:
   `[LinkHealth] Marked 1 interrupted job(s) as failed after restart: 10`; DB job 10 failed 'Interrupted by server restart';
   /admin/export shows "Link check #10 FAILED … Interrupted by server restart".
