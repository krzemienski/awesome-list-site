# D06: Approvals and edit approvals left cached admin tables and public taxonomy stale (VERIFIED)

**Environment.** DEV app (`npm run dev`, workflow "Start application", http://127.0.0.1:5000), restarted after the last server edit on 2026-10-09. Admin calls use the `X-Admin-Audit-Key` header (value comes from the ADMIN_PASSWORD secret, never logged) plus an `Origin` header. Harness sources: `evidence-583/harness/` (`lib.mjs` wraps fetch and psql and records every request, status, response excerpt and SQL result). Fixtures all start with `__qa_test_plan_583_`, are deleted by exact id, and each run ends with this residue query:

```sql
select (select count(*) from resources where title like '__qa_test_plan_583_%' or url like '%__qa_test_plan_583_%') as resources,
       (select count(*) from categories where name like '__qa_test_plan_583_%') as categories,
       (select count(*) from subcategories where name like '__qa_test_plan_583_%') as subcategories,
       (select count(*) from sub_subcategories where name like '__qa_test_plan_583_%') as sub_subcategories,
       (select count(*) from resource_edits e where not exists (select 1 from resources r where r.id = e.resource_id)) as orphan_edits;
```

## Before
Audit source trace:
- PendingResources and PendingEdits invalidated only their own queues and stats.
- ResourceManager and GenericCrudManager omitted the awesome-list listing caches.
- Shared query defaults are staleTime Infinity with no focus refetch.

There was also a second, lower layer: catalog GETs carry `Cache-Control: public, max-age=60`. Even an invalidated query refetched the **browser HTTP-cached** pre-mutation body for up to 60 s.

## Fix
- `apiRequest` calls `invalidateCatalogQueries()` after every successful admin catalog write. It is one shared graph covering public resources and details, taxonomy, admin queues, resources, taxonomy, stats and audit, and every awesome-list nav, data and listing cache.
- For 60 s after a catalog write in the tab, catalog reads use `cache: 'no-cache'`. They revalidate with the ETag (304/200) instead of reusing the HTTP cache. This covers the default query fetcher, `apiRequest` GETs and the static-data fetcher.
- GenericCrudManager parent queries use one top-level `useQueries` (no hooks inside a map).
