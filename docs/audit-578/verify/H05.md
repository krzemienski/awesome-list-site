# H05 — Compatibility redirects discard pagination and active discovery filters

**Status: FIXED and proven on DEV (2026-10-09).**

## Before (from the audit)
- `/subsubcategory/av1?page=2` redirected without `page`.
- The nested category alias dropped its query.
- `/explore?category=…&sort=…` kept only `q`.

## Fix
- og-middleware alias targets and the client compatibility routes in `client/src/App.tsx` use one safe query-preserving builder. It keeps `page` and the supported discovery params and lets the destination validate the range.
- App.tsx nested `/category/:cat/:sub` redirects only when `:sub` is a real child; otherwise it renders NotFound.
- The auth `next` mapping is unchanged.

## Recipe executed
curl (DEV):
```
/subsubcategory/av1?page=2 -> 301 /sub-subcategory/av1?page=2
/explore?category=encoding-codecs&sort=name-asc -> 301 /search?category=encoding-codecs&sort=name-asc
/explore?q=ffmpeg&tags=open-source&page=2 -> 301 /search?q=ffmpeg&tags=open-source&page=2
/category/encoding-codecs/codecs?page=2&sort=name-asc -> 301 /subcategory/codecs?sort=name-asc&page=2
/category/encoding-codecs/nope-587 -> 404
```
