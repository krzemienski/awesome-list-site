## Defect 1 — panel mounts spent the AI rate limit

**Before.** Every signed-in mount of the recommendations panel (Home, Profile, Recommendations, Advanced tab) sent `POST /api/recommendations`. That route sits behind `aiLimiter` (10 requests per 15 minutes per client, shared Postgres store, limiter `ai-generation`). Usually the server answers from its own 30-minute cache without calling the model, but each POST still counts. A few minutes of moving between account pages produced the error card "Too many AI requests" with zero model calls (`shots-592/V06-before-429-rate-limit-desktop.png`).

**Fix (client only; the server limit is unchanged, because it is the only cap on recommendation generation).**
- `useAIRecommendations` stores the profile fingerprint with the device cache entry and exports `hasFreshRecommendationsCache(userId, fingerprint)`.
- `AIRecommendationsPanel`: on a signed-in first mount, if this device has results under 5 minutes old for the same profile, it shows them and skips the POST. Refresh always asks the server; stale results still refresh in the background; saving preferences already clears the cache.
- `useRecommendationFeedback`: if clearing a choice (Undo / Restore) targets a card that is no longer in the stored list, the device cache is removed so the next surface asks the server and the restored card is not lost.

**After.** Part B and the supplement: Home, Profile and the Advanced tab send no POST; the whole V06 run used 8 POSTs, below the 10 limit, where the previous version hit 429 part-way through.

## Defect 2 — offline Refresh hung with no message

**Before.** React Query pauses mutations while the browser is offline. The button read "Refreshing…" indefinitely and nothing explained why.
**After.** `useAIRecommendations` exposes `isPaused`. The panel then shows the "You’re offline" notice (`data-testid="offline-refresh-state"`) and the label "Waiting for connection…", keeps the saved cards, and resumes on reconnect (`shots-592/V06-cold-offline-refresh-desktop.png`).
