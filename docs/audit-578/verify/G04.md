# G04 — Cancellation is truthful and never rewrites history

**Status: PROVEN (2026-10-09, scratch DB + live paid runs on scratch)**

## Fix
The landed changes were reviewed and kept:
- `EnrichmentRepository` / `enrichmentService` / `researchService` cancel with a conditional `UPDATE … WHERE id=? AND status IN (active)`, then classify the outcome:
  - missing → 404
  - terminal (completed / failed) → **409 "Only active jobs can be cancelled"**, row untouched
  - already cancelled → idempotent 200 no-op
  - active → 200 and the job becomes cancelled
- `ai-jobs.ts` routes map those outcomes to HTTP status.

Added in this task:
- `server/routes/domains/ai-jobs.ts`: both `DELETE …/jobs/:id` routes reject non-int4 ids with 400 instead of a DB error.
- `server/ai/runAgentQuery.ts` accumulates deduplicated streamed usage. An aborted run therefore records the tokens it had already used instead of 0.
- `server/ai/researchService.ts`: `abortedWithNoUsage` now also requires zero tokens, so a cancelled run with usage is not treated as an empty run.
- Limitation: streamed usage is a lower bound, and the SDK reports no cost for aborted runs.
