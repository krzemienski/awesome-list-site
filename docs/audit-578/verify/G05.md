# G05 — Researcher cancel failures are visible and retryable

**Status: PROVEN (2026-10-09, real browser, DEV app :5000)**

## Fix
These landed changes in `client/src/components/admin/ResearcherTab.tsx` were reviewed and kept:
- `cancelMutation.onError` shows a destructive toast with a **Retry** action.
- An inline `role="alert"` banner, "Could not cancel job #N: …", has a **Retry cancellation** button that is disabled while the request is pending.
- The job list is refreshed only on success, so a job stays active until the server confirms the cancel.

Added in this task: `aria-label`s ("Approve discovery: …" / "Reject discovery: …") on the icon-only moderation buttons in the job-details dialog.

## Before
`cancelMutation` had only `onSuccess`. Network, 409 and 500 failures were silent (static audit evidence).
