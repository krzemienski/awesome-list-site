# H10 — Resource detail category chip always shows the protocols glyph ⟁

**Status: FIXED and proven on DEV (2026-10-09).**

## Before
`ResourceDetail.tsx` hard-coded `⟁` for every category. The sweep screenshot of `/resource/184739` (Standards & Industry) showed ⟁.

## Fix
ResourceDetail reads the glyph from the single shared map in `client/src/lib/category-glyph.ts`, the same source home cards use.

## Recipe executed
Script: `evidence-587/h10.mjs` → `h10-out.txt`. It runs in all 5 systems (editorial, terminal, geist, brutalist, swiss) at 375 and 1440. For each run it opens the resource page and reads the chip glyph, then opens home and reads the glyph on that category's card:
```
{"system":"editorial","w":375,"id":184739,"slug":"standards-industry","chipLabel":"◉ STANDARDS & INDUSTRY","homeGlyph":"◉","match":true}
{"system":"editorial","w":375,"id":185020,"slug":"protocols-transport","chipLabel":"⟁ PROTOCOLS & TRANSPORT","homeGlyph":"⟁","match":true}
... (20 rows, all match:true) → ALL_MATCH
```

## Note: glyph rendering, outside this item
In this container's headless Chromium, `⟁` (U+27C1) has no installed font and draws as a tofu box. This affects the resource chip, the home cards and the footer equally. The *value* is correct and matches home. Whether the glyph renders on devices without a symbol font is a separate font-coverage question and was not changed here.
