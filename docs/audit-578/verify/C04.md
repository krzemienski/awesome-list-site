# C04 — Malformed edit shapes return 400, never 500; no-op edits are refused

**Status: FIXED — proven on DEV, 2026-10-09 (run `__qa_test_plan_582_1791561997330`)**

## Before
Per the audit: `POST /api/resources/188642/edits {"proposedData":"string","proposedChanges":"string"}` → **500**.
Numeric, boolean and string `proposedData` and numeric `proposedChanges` → 500 (qa-108..qa-111). Cause: a truthiness test
followed by the `in` operator on an unvalidated primitive.

## Fix
`catalog-contributions.ts` parses the body strictly before reading any field:
- `proposedData` must be a non-null, non-array, non-empty object with editable keys only.
- Each value is type-checked (strings, tags array, single taxonomy names).
- `proposedChanges`, if sent, must be an object of `{old,new}` entries equal to the server-derived diff.
- An edit whose derived diff is empty → 400 "An edit must change at least one field".

## Proof (ordinary throwaway user, owned QA resource 188644)
