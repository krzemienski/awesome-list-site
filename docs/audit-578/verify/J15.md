# J15 — Live tag check has fixed vocabulary and sparse failure diagnostics

**Status: PROVEN (2026-10-09, DEV + scratch DB clone)**

## Fix
`scripts/validation/tag-route-audit.mjs`:
- **Eligible-tag discovery.** The audit reads the real metadata-derived tag facets (`GET /api/resources?limit=1&facets=true`) and picks a canonical tag that reaches the landing threshold of **5** approved resources. The slug is normalized with `shared/tagNormalize.ts`. This replaces the fixed list `encoding/player/streaming/video/audio`. An explicit override is still honoured.
- If no tag is eligible, the audit fails explicitly with the largest candidate, for example `-qa-test-plan-codec-lab=4`.
- **Diagnostics.** `tag-route-audit.json` is always written. It holds:
  - the discovery request (status, a bounded body excerpt on error, facet counts);
  - the tag;
  - per page: the final URL, title, h1, rendered card count, results total, console errors, page errors, failed requests, API error bodies and in-flight API requests;
  - failure screenshots.
- `.github/workflows/deploy.yml`: the failure message points to that artifact.

## Completion-run finding (2026-10-10)
In one completion validation run, `direct-redirect` failed. The retained diagnostics were enough to explain it without a rerun, which is the property this item adds: `pages.direct = {finalUrl:"/categories", h1:null, cards:0, console:["…status of 503 (Service Unavailable)"]}`.

The 503 came from the DB-resilience gate's deliberate table lock, which ran in parallel with this audit. This audit had never taken the shared `db-heavy` gate lease that other crawl gates use. It now takes that lease. Standalone rerun: `Gate lease acquired (db-heavy: tag-route-audit)` … `TOTAL 5, FAIL 0`.
