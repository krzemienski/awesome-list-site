   - The `result` event (seq 20) carried `cost_usd 0.3082`, tokens 4/897 and `num_turns 3`, with detail `{"subtype":"error_max_budget_usd","is_error":true}`.
   - The job row recorded `turns_used 0, total_input_tokens 0, total_output_tokens 0, estimated_cost_usd 0.00`.

## Root cause and fix

- **Cause.** `server/ai/runAgentQuery.ts` captures usage from the `result` message into a local `result` object. When `is_error` is true it throws, and the usage is lost with that local object. `researchService`'s `.catch` then marked the job failed without any usage. The enrichment failure path had the same gap (`processJob` catch).
- **Fix (3 files):**
  - `runAgentQuery.ts`: the rethrow path attaches `agentUsage {numTurns, tokensIn, tokensOut, totalCostUsd}` to the error. It uses the result message when one arrived, otherwise the streamed token counts. A new exported helper, `agentUsageFromError()`, returns that usage, or null when nothing was observed.
  - `researchService.ts`: the failure handler writes `turnsUsed/totalInputTokens/totalOutputTokens/estimatedCostUsd` from that usage.
  - `enrichmentService.ts`: the failure handler folds the usage into the run totals before `buildJobMetadata`.

## 3. Re-proof after the fix (paid #7, job 57)

I restarted A and ran a research job with budget $0.05, 12 turns, target 1:

```
job    {"status":"failed","error":"…Reached maximum budget ($0.05)","turnsUsed":2,"inTok":0,"outTok":0,"cost":"0.1162"}
result {"seq":7,"tokensIn":0,"tokensOut":0,"cost":"0.1162","detail":{"subtype":"error_max_budget_usd","is_error":true,"num_turns":2}}
match  {"turns":true,"tokensIn":true,"tokensOut":true,"cost":true}
```

- Before the fix: 0 turns / $0.00 against a $0.3082 run.
- After the fix: the row equals the SDK's own report (2 turns, $0.1162).
- Observation, not changed: the SDK checks the budget cap between turns, so one opus turn can overshoot a small cap. Here a $0.05 cap ended at $0.1162.
