# E04: Overview's pending-approval tile could stay stale

**Status: FIXED, proven on DEV (2026-10-09)**

## Root cause (confirmed)
`AdminStats` read the tile count from its own pending-resources query (staleTime 30 s, no polling, no focus refetch),
and that count took priority over the polled `stats.totalPending`. The oldest-age subtext came from the same stale
snapshot.

## Fix
- `AdminStats.tsx`: the tile count is now the polled authoritative `stats.totalPending`. The oldest-pending query that
  feeds the subtext polls on the same 30 s cadence (`refetchInterval`, focus refetch, finite staleTime). It is only
  used for the age, never to override the count.
- `useAdmin.ts` / `AdminDashboard.tsx`: a failed background stats poll now keeps the last good snapshot instead of
  replacing the whole dashboard with "Error loading admin dashboard". Only a first-load failure or a 401 replaces it.
  This was found during the E05 outage run, where one failed poll blanked the admin console.

## End-user recipe (executed)
Script `/tmp/e04e05.mjs e04`. Owner admin on `/admin/overview` on :5000; a second client used curl-equivalent fetch
with a separate cookie. Log: `logs/E04-run.txt`.
```
baseline tile: PENDING APPROVALS 0 nothing waiting | SQL pending: 0
second client POST /api/resources -> 201 {"id":188646,"status":"pending"}
tile changed after 28s -> PENDING APPROVALS 1 oldest 26s ago        marker: set-once
second client reject -> 200
tile changed after 28s -> PENDING APPROVALS 0 nothing waiting       marker: set-once
```
`marker: set-once` is a window variable set once before the run. It was still present afterwards, so the page never
reloaded or remounted. There was no focus switching or manual refresh. Both changes landed within the advertised 30 s.
