# B02 — Published journeys exposed rejected resources

**Status: FIXED and proven** on DEV, 2026-10-09 (API, server HTML and real browser at desktop 1366px and 390px).

## Before (audit evidence)
- 6 rejected resources linked from published journeys 6, 9 and 10: 184980, 186453, 184773, 186448, 185324, 185082.
- Anonymous `/api/journeys/6` exposed step 178 → resource 184980 (rejected Otterbein title/URL/description). Journey 6 HTML contained the same title. The outbound URL returned 404.
- Pending QA resource 188641 had its title, URL and description exposed on a published journey.
- Cause: `listJourneySteps` left-joined resources with no approved-status predicate.

## Fix
- `LearningJourneyRepository.listJourneySteps(journeyId, { includeUnapproved })` joins resources with `status = 'approved'` by default and passes them through the shared `stripInternalResourceFields` projection (`server/lib/publicResource.ts`). Only admin editing passes `includeUnapproved: true`.
- A step whose resource is not approved keeps its row and `resourceId`, so logical step and completion semantics are unchanged. Its `resource` is `null`.
  - Server HTML and the client (`JourneyDetail.tsx`) show "Some resources in this step are no longer available. Your step progress is unchanged."
  - No title, URL or description is sent.
- After the shared projection runs, the embed is narrowed back to the documented `JourneyStepResource` shape: `id, title, url, description, kind, resolvedKind`. The projection had widened it to include taxonomy and metadata.
  - Re-checked with curl after a restart: journeys 6/7/9/10 each return 18 rows with exactly those 6 keys, and the null-resource rows are 178 / none / 226,228,229,231 / 241.
  - `/journey/6` HTML returns 200, contains 2 "no longer available" notes and 0 "Otterbein" matches.
  - Later change for SEO parity (the seo-snapshot gate flagged a crawler/client step-description mismatch on /journey/10). The server no longer appends the note to the step description. It sets a `hasUnavailableResources` flag, and `renderJourneyContent` prints a separate `<p class="ssr-meta">Some resources in this step are no longer available.</p>`, so `data-seo-step-description` now matches the client exactly.
    - curl after a restart: `/journey/10` contains that `<p class="ssr-meta">`, and `/journey/6` has 1 "no longer available" occurrence.
    - The JSON-LD syllabus description is now the stored step text.
  - Integration test `resource-kinds.test.ts › journey step resources` passes.
- The 6 rejected resources were **not** modified. They stay rejected.
