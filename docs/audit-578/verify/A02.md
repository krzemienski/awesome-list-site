# A02 — Bookmarks and favorites disclose other contributors' non-public resources

**Status: FIXED — proven on DEV 2026-10-09 16:07–16:08 UTC (run `__qa_test_plan_580_1791562070462`).**

## Fix
- `POST /api/favorites/:id` and `POST /api/bookmarks/:id` load the resource and return `404 {"message":"Resource not found"}` unless
  `status === "approved"` (owners included — the ordinary save path is for public resources).
- `UserFeatureRepository.getUserFavorites/getUserBookmarks` join with `resources.status = 'approved'`, so a resource that leaves public
  status disappears from lists without exposing its moderation state. The user's row is kept (it reappears if re-approved).
- `POST /api/interactions` 404s for non-approved resources; continue-learning shows "Unavailable resource" for non-approved history.
