## Results (1440 and 390)

| Step | Observed |
|---|---|
| `/about` → "link-about-deletion"; `/privacy` → "link-privacy-deletion" | both land on `/profile?tab=security`; Security tab trigger `aria-selected="true"`, panel `data-state="active"`, deletion card visible |
| Request account deletion → **Cancel** | DB `deletion_requested_at` stays NULL; focus returns to `button-request-deletion` |
| Keyboard: Enter opens the dialog, **Escape** closes it | NULL; focus back on `button-request-deletion` |
| Request → **Request deletion** | toast "Deletion request submitted…"; DB timestamp set |
| Reload | "Your deletion request from 10/10/2026 is pending…" plus a Withdraw button |
| Repeat `POST /api/user/deletion-request` from the page | **200** `alreadyRequested:true`, same timestamp (idempotent) |
| Approved resource count before vs after | delta **0** (a request deletes nothing) |
| **Withdraw** | DB NULL; toast "Deletion request withdrawn — Your account will not be deleted."; Request button back and focused |
| Second device (context 2) signed in as A; device 1 opens **Sign out all devices** → **Cancel** | both still authenticated; focus back on `button-logout-all` |
| → **Confirm** | device 1 lands on `/` signed out; device 2 after reload `isAuthenticated:false`; Clerk `GET /sessions?user_id=A` → all 3 sessions `revoked` |
| Two new devices 3 and 4 for A; device 3 has a submit draft in localStorage → Profile **Sign out** | device 3 `/api/auth/user` unauthenticated and `submit-resource-draft` removed; **device 4 still authenticated after reload** (only the current session ended) |
| Device 3 signed out → `/profile` | redirected to **`/sign-in?redirect_url=%2Fprofile`** (return destination kept). `/bookmarks` is guest-capable and shows "Nothing saved on this device…" instead of A's saved item |
| Same device signs in as B → `/bookmarks` | `/api/auth/user` = B; B bookmarks 0 (A has 1); page HTML has no trace of A's id or name; no draft; no `ai_recommendations_cache:<A>` key |
