# E06: API key management had no user interface

**Status: FIXED, proven on DEV (2026-10-09)**

## Root cause (confirmed)
`/api/user/api-keys` (create/list/revoke) existed in `user-features.ts`, but nothing in `client/src` used it. Profile
Security only offered Clerk's account-security modal.

## Fix
- New `client/src/components/profile/ApiKeysCard.tsx`, rendered in Profile → Security below the account-security
  card. It provides:
  - a create form: name, expiry 30/90/365 days or never
  - a **one-time secret panel** with Copy and copy status, and "I've saved it" to dismiss. The secret is held only
    in component state and never refetched.
  - a non-secret list: name, ACTIVE/REVOKED/EXPIRED status, created/expires/revoked/last-used
  - a revoke confirmation dialog
  - inline error alerts that say existing keys are unchanged. A network failure reads "The server couldn't be
    reached. Check your connection and try again."
- `AccountSecurityCard.tsx` copy now says app API keys are managed separately below, so it no longer implies Clerk's
  modal manages them.

## Before / after
Before: there was no way to create, see or revoke keys from the site. After: the full lifecycle works on desktop and
mobile. The secret is shown exactly once, revocation takes effect on key auth immediately (401), and failures leave
keys untouched.
