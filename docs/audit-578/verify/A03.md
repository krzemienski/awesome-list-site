# A03 — Bookmark notes accept objects instead of the UI's bounded text contract

**Status: FIXED — proven on DEV 2026-10-09 16:07–16:08 UTC (run `__qa_test_plan_580_1791562070462`).**

## Fix
`POST /api/bookmarks/:id` validates `notes` before any write: omitted = keep existing note; otherwise it must be a string of at most
500 characters with no control characters other than tab/LF/CR. Anything else → `400` with a `validation_failed` envelope and the stored
note is untouched. Markup policy: notes are plain text, stored verbatim and rendered as text by React (no HTML rendering anywhere).

## Recipe executed (throwaway Clerk user B on approved R1 = 188654)
Each 400 case was followed by `GET /api/bookmarks` to confirm the prior note was unchanged.

| Request body | Status | Prior note kept |
|---|---|---|
| `{"notes":"…line one\nline two\r\n\ttabbed <script>alert(1)</script> & \"quotes\""}` | 200, round-trips verbatim | — |
| `{"notes":{"bad":true}}` | 400 | yes |
| `{"notes":["a","b"]}` | 400 | yes |
| `{"notes":true}` | 400 | yes |
| `{"notes":42}` | 400 | yes |
| `{"notes":null}` | 400 | yes |
| `{"notes":"x"×501}` | 400 | yes |
| `{"notes":"bell\u0007"}` | 400 (`fieldErrors.notes: must not contain control characters`) | yes |
| `{"notes":"nul\u0000"}` | 400 | yes |
| `{"notes":"y"×500}` | 200, stored 500 chars | — |
| `{}` (bare duplicate save) | 200, 500-char note preserved | — |
| `{"notes":""}` | 200 `{"notes":""}`; DB `notes = ''`; list omits the empty note | — |

400 body excerpt: `{"message":"notes must be a plain-text string of at most 500 characters without control characters","error":"validation_failed",…}`

## Before / after

- **After**: every non-string / oversized / control-character note → 400 and the previous annotation survives.
