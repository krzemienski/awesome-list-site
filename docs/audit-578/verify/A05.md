# A05 — Public developer tag API is empty although the catalog has 1,535 tags

**Status: FIXED on DEV (proven 2026-10-09 16:08 UTC). Production still serves the old tags-table payload until the next publish.**

## Fix
`GET /api/public/tags` calls the same `listApprovedResourceTags()` aggregation as `GET /api/tags` (approved resources'
`metadata.tags`, usage counts), and both share the `ApprovedResourceTagsResponse` contract. The empty/unused `tags` table is no longer read.

## Recipe executed (DEV, real app)
- `GET /api/public/tags` vs `GET /api/tags`: **byte-identical JSON** (`JSON.stringify` equality), 1,536 tags each, `total: 1536`.
  (1,535 catalog tags + the run's own fixture tag `qa-test-plan-580-mv15ssse`, which appears with `count: 1`.)
- SQL: `count(DISTINCT lower(tag))` over approved resources' `metadata.tags` = 1,536 — matches.
- Top of list: `open-source 158, video-streaming 118, streaming 100, video-processing 81, ffmpeg 78`.
- Tag search is usable: `GET /api/resources?tags=open-source&limit=1` → `total: 158` = the tag's count.

## Production (read-only)
2026-10-09 ~16:12 UTC:
- `GET https://awesome.video/api/public/tags` → 200, 1,608 rows shaped `{id,name,slug,createdAt}` (the `tags` table, no counts).
- `GET https://awesome.video/api/tags` → 200, 1,541 approved-resource tags with counts.
- Not equal — production runs the pre-fix route. This is the "before" state on prod; it becomes equal after the next publish.
  Publishing is outside this task's read-only production rule.
