# F08 — Link-health read failures are shown as errors with Retry, never as empty data

Status: **FIXED + PROVEN** (scratch DB, browser desktop + mobile)

## Before
LinkHealthDashboard ignored query errors; a failed read rendered "No link health data available yet" / zero counts (audit OPS-05).

## Fix
Each dataset distinguishes loading, verified empty and failed reads; failures show an alert naming the failed request with a Retry button, keep last known data labelled stale,
and suppress "no data"/"all clear" copy.

## Steps / evidence
Playwright `page.route(...).abort()` on each endpoint individually (the DevTools "block request" equivalent), /admin/linkhealth:
- desktop: `/api/admin/link-health/status`, `/history`, `/broken-links`; mobile: `/status`.
- Each blocked load: alert "Link health data could not be refreshed…" with a Retry button for that request and "Link health results unavailable until the failed requests recover";
  no "No link health data" and no all-clear/zero-count copy.
- Unroute + click Retry: alert gone, Healthy 2 / Broken 8 shown.
