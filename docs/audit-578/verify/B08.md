# B08 — Step editor reset typed changes while saving

**Status: FIXED and proven** in a real browser at `/admin/journeys`, desktop 1366px and 390px, 2026-10-09.

## Before (audit evidence)
Source trace: `StepEditor` reset its form whenever the identity of `initial` changed. The parent built a new `initial` object on every render, so `updateMutation.isPending` flipping on Save reset the form to the stored values. Errors were toast-only.

## Fix
`JourneyStepsManager.tsx`:
- `StepEditor` initialises its form only when it opens or its `targetId` (the group's primary row) changes. Parent re-renders during pending or error states no longer touch the draft.
- Mutation errors render inline (`p[role=alert]`) inside the dialog, which stays open.
- 5xx errors (whose body the server contract masks) get an actionable "Nothing was changed because the server hit an error. Reload the steps and try again."
- Group edits PATCH the primary row with `?group=true` and update all rows of the group in one transaction.

## Proof — `browser-admin.mjs edit <vp>` → `out/browser-admin-edit-{desktop,390}.json`
Signed-in throwaway admin, draft QA journey (group 1 = 3 rows, group 2 = 2 rows, group 3 = 1 row).

**Single-row step (group 3):**
1. Changed title, description, ticked optional, and picked a different resource (#184745).
2. The PATCH was **held** by `page.route`, then Save was clicked. After 1.2 s pending: title, description, `optional=checked` and resource chip are all retained, and the button reads "Saving…".
3. Released the hold with a **forced 500**:
   - The dialog is still open with the same draft.
   - Inline alert: "Nothing was changed because the server hit an error. Reload the steps and try again." No toast.
   - SQL row unchanged.
4. Clicked Save again, request continued to the real server → 200, dialog closes. SQL: `title`/`description` updated, `is_optional=true`, `resource_id=184745`.
5. A **real 400** (stale resource) is covered in B06: inline error, draft kept, then corrected and saved.

**Three-row group (group 1):**
1. Edited title and ticked optional. The PATCH was held: draft retained, "Saving…".
2. Released to the real server → 200. SQL: **all 3 rows** have the new title and `is_optional=true`, with their resource ids unchanged.

Same results at desktop and 390px.
