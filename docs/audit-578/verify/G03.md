# G03: Researcher approvals bypassed approval provenance and audit logging (VERIFIED)

**Environment.** Scratch DB `awesome_scratch_590`, a `pg_dump` clone of DEV, served by:
- **After fix:** the working tree on port 5190.
- **Before fix:** the pre-fix code (HEAD 3e85c8b7) on port 5191.

Both instances ran with background jobs disabled.
- **API calls:** `X-Admin-Audit-Key` header plus `Origin`.
- **Browser:** real Chromium (Playwright from the repo). The audit-key header is added only to same-origin requests via route interception. The acting admin is `admin@example.com`, id `d460f5e7-a085-4083-96a2-2f20dc9315c4`.

## Before
- **Audit finding:** 10 `ai_researcher` resources had `approved_at NULL`. The approval path inserted `status='approved'` directly, with no approvedAt, approvedBy, statusChangedAt or audit row, and the routes never passed the acting admin.
- **Reproduced on the pre-fix code** (`evidence-590/logs/G02-G03-before-oldcode.json`): the approved resource 188658 had `approved_at null`, `approved_by null`, `status_changed_at null` and `audit null`.

## Fix
- **Routes.** Both `POST /api/researcher/discoveries/:id/approve` and `POST /api/researcher/discoveries/approve-all` pass `req.dbUser.id`. The bulk path forwards it for every discovery.
- **Approval.** Each approval inserts the resource as `pending`, then publishes it with the shared `transitionResourceInTransaction`, inside the same transaction as the discovery update. That helper:
  - applies the description gate (a too-short description is filled from title and host)
  - stamps `approvedAt`, `approvedBy` (the acting admin) and `statusChangedAt`
  - writes one `approved` audit row with `performed_by` = the admin, `changes {previousStatus:'pending', newStatus:'approved'}`, and the note `AI researcher approval: discovery #N (research job #M)`
- **Visibility.** Provenance is visible to admins only. The public serializer does not return it.
