# D01: Renaming or moving taxonomy nodes leaves resource labels orphaned (VERIFIED)

**Environment.** DEV app (`npm run dev`, workflow "Start application", http://127.0.0.1:5000), restarted after the last server edit on 2026-10-09. Admin calls use the `X-Admin-Audit-Key` header (value comes from the ADMIN_PASSWORD secret, never logged) plus an `Origin` header. Harness sources: `evidence-583/harness/` (`lib.mjs` wraps fetch and psql and records every request, status, response excerpt and SQL result). Fixtures all start with `__qa_test_plan_583_`, are deleted by exact id, and each run ends with this residue query:

```sql
select (select count(*) from resources where title like '__qa_test_plan_583_%' or url like '%__qa_test_plan_583_%') as resources,
       (select count(*) from categories where name like '__qa_test_plan_583_%') as categories,
       (select count(*) from subcategories where name like '__qa_test_plan_583_%') as subcategories,
       (select count(*) from sub_subcategories where name like '__qa_test_plan_583_%') as sub_subcategories,
       (select count(*) from resource_edits e where not exists (select 1 from resources r where r.id = e.resource_id)) as orphan_edits;
```

## Before
Audit evidence (evidence.json / evidence2.json): PATCH on category 1555, subcategory 2305 and leaf 3751 returned 200, but SQL showed the resources still carrying the OLD labels. Moving subcategory 2310 to category 1562 left resource 188638 on the old category name.

## Fix
- `CategoryRepository` updates for category, subcategory and leaf run in one transaction. The transaction rewrites the resource label columns, scoped to the full parent chain (category > subcategory > leaf), so a same-name subcategory under another category is not touched. A category rename also relabels `learning_journeys.category`. A subcategory move rewrites the category of every resource in that subcategory, leaf rows included.
- A name-only rename keeps the existing slug. The public cache is invalidated after commit.

## Executed proof (scratch DB)
This rename/move touches many rows, so it ran on a **scratch database cloned from DEV** (`createdb` + `pg_dump` DEV piped into `psql`). A second instance served it: `PORT=5183 DISABLE_BACKGROUND_JOBS=1 DATABASE_URL=<scratch> npx tsx server/index.ts`, killed by its own PID afterwards.
*Deviation from the generic ground rule:* background jobs were **disabled** on this instance. With them enabled, the job workers would start AI enrichment on the 40 new resources, and this task's paid-AI budget is 0. The rename/move code path does not depend on any background job.

Command: `BASE_URL=http://127.0.0.1:5183 PROOF_DATABASE_URL=<scratch> node evidence-583/harness/d01-scratch.mjs`. Log: `evidence-583/logs/d01.log`. JSON: `evidence-583/logs/out-d01/D01.json`.

Fixtures:
- 3 QA categories (cat1, cat2, decoy), a subcategory under cat1, a **same-name decoy subcategory** under the decoy category, and a leaf.
- 40 resources: 20 approved in the subcategory, 5 pending in the subcategory, 10 approved in the leaf, 3 approved at category level, and 2 under the decoy.
- 1 draft journey labelled with cat1.

Responses (excerpts):

Assertions (all PASS):
- category rename 200 and slug preserved
- all 38 category-1 resources follow the new category name; the decoy resources are untouched
- the journey category label follows the rename
- subcategory rename 200 and slug preserved; 35 subcategory resources (leaf and pending included) carry the new name
- the same-name decoy subcategory under the other category keeps its label (scoped cascade)
- leaf rename 200 and slug preserved; 10 leaf resources carry the full new chain
- move 200; all 35 subcategory resources (leaf included) moved to category 2; 3 category-level resources stay in renamed category 1
- every resource label chain resolves to a real taxonomy chain
- public nav (sidebar sums): category 2 = 30, moved subcategory = 30, renamed leaf = 10 approved; renamed category 1 = 3; old category name gone
- public listings reachable: subcategory under category 2 = 30, leaf = 10, category 1 = 3
- admin listing shows 35 rows in category 2 with the new subcategory label; admin subcategory count (all statuses) = 35

The same cascade is shown in the real admin UI on DEV by D06 part B: renaming a category and moving a subcategory through the admin dialogs. See `D06.md`.

Residue after the run: `{"resources":0,"categories":0,"subcategories":0,"sub_subcategories":0,"orphan_edits":0}`. The scratch database was then dropped. `select datname from pg_database where datname like 'awesome_scratch%'` returns 0 rows.
