# C05 — Duplicate suggested URLs are rejected with an actionable 409 (submission, approval, race)

**Status: FIXED — proven on DEV, 2026-10-09 (run `__qa_test_plan_582_1791561997330`)**

## Before
Per the audit: submission validated only URL syntax. Approval updated `resources.url` directly. A pending edit proposing
another resource's URL → approve **500 Internal Server Error** (evidence2.json).

## Fix
- **Submission** (`catalog-contributions.ts`): a URL owned by another resource → **409** with `field:"url"`,
  `conflictingResourceId` and `title` (named only when that resource is public). No edit is created.
- **Dialog** (`suggest-edit-dialog.tsx`): a 409 with `field:"url"` is shown inline under the URL input
  (`form.setError`), not as a toast.
- **Approval** (`AuditRepository.approveResourceEdit`): inside the locked transaction, a URL precheck throws
  `EDIT_URL_CONFLICT`. `admin-content.ts` approve maps that, and a wrapped PostgreSQL `23505` on the URL unique
  index, to **409** "That URL already belongs to another resource (#id: "title"). Revise or reject the suggestion; it
  stays pending." with `conflictingResourceId`/`title`. The transaction rolls back, so the resource and edit are untouched.

## Proof — submission
- API (`api-proof.json`): A (188647) → B's URL: **409** `That URL already belongs to another resource (#188648:
  "…_url_b"). Suggest a different URL…`, `field:url`, `conflictingResourceId:188648`. Edits on A afterwards: **0**.
- Browser (`browser-submitter.json`): the submitter opens Suggest Edit on 188651 and types A's URL → Submit. The request
  body is `{"proposedData":{"url":"…_url_a"}}`; the response is 409. The URL input gets `aria-invalid="true"` and the
  inline message "That URL already belongs to another resource (#188647: "…_url_a"). Suggest a different URL, or suggest
  edits on that resource instead." Edits created: **0**. Screenshot: `evidence-582/C05-dialog-inline-409.png` (opened).
- The admin Analyze flow hit the same inline 409 against the real catalog resource #185662 (see C03 step 4).

## Proof — approval after another resource takes the URL (sequential race)
1. A valid proposal for A → `…_race_target`: 201 (edit 71).
2. Admin `PUT` moves B onto `…_race_target`: 200.
3. Approve edit 71 → **409** naming `#188648 "…_url_b"`. Edit 71 still `pending`; A's URL unchanged.

## Proof — true database race (23505 path), `race23505.mjs`
A competing transaction holds B's URL update **uncommitted**, so the approval's precheck sees the URL as free. The
approval UPDATE then blocks on the unique index until the competitor commits (1.2 s later):
- Approve → **409** `…(#188648: "…_url_b"). Revise or reject the suggestion; it stays pending.`,
  `conflictingResourceId:188648`.
- Server log (`evidence-582/workflow-23505-excerpt.log`): `duplicate key value violates unique constraint
  "resources_url_unique"`, `code: '23505'`. This is the real constraint path, mapped to 409.
- After: race resource title/url unchanged; edit 79 `pending`.

Observed edge, documented rather than changed: when the competitor held its lock longer than the pool's
`lock_timeout=2000ms` (first attempt, 2.5 s hold), the approval returned **503 "Service is temporarily unavailable"**
with Retry-After (55P03 lock timeout; `workflow-55P03-excerpt.log`, `race23505-locktimeout.json`). The resource was
unchanged and the edit stayed pending. That is the app-wide transient-DB policy, not a 500, and retrying then yields the 409.

## Proof — concurrent rounds
Four rounds firing approve and a competing admin move at the same time (`api-proof.json`, "C05 concurrent round 0–3"):
each round resolved with exactly one owner of the URL (approve 200 + move 409 "Another resource already uses this URL").
No 500.

## Proof — admin UI
`browser-admin-run2.json`: on `/admin/edits`, Approve on edit 79 (whose URL B now owns) → Approve & Merge. The dialog
shows "That URL already belongs to another resource (#188648: "…_url_b"). Revise or reject the suggestion; it stays
pending." Response 409. Screenshot: `evidence-582/C05-admin-approve-409.png` (opened).
Unique-URL approval succeeds: edit 69 → 200 (C01). Edit 71 was also approved (200) once B had moved off its URL during
the concurrent rounds, which is the expected normal path.
