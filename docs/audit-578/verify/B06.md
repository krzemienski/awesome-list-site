# B06 — Missing resource ids reached the database and returned 500

**Status: FIXED and proven** via API and a real browser (stale picker selection), desktop and 390px, 2026-10-09.

## Before (audit evidence)
- `POST /api/admin/journeys/15/steps {resourceId:2147483647}` → **500**.
- `PATCH /api/admin/journeys/19/steps/272` with the same id → **500**.
- Cause: the numeric range was validated, but whether the resource existed was not.

## Fix
- POST and PATCH check, before writing, that the resource exists and is `approved`. The check runs inside the write transaction (`SELECT … FOR SHARE`), so a concurrent delete cannot slip between check and insert.
  - A missing or non-approved resource → `400 "Selected resource no longer exists or is not approved. Choose another resource."`
  - An FK race maps to the same 400.
  - A step id that no longer exists → 404/409 "Step no longer exists. Reload the steps."
- The editor shows the server message inline and keeps the dialog and draft (see B08).

## Proof — browser (`browser-admin.mjs edit <vp>` → `out/browser-admin-edit-{desktop,390}.json` → `b06_*`)
1. Inserted an approved QA resource `__qa_test_plan_581_stale_pick_*`.
2. In the UI: Steps → Edit (single-row step) → typed a new title → Pick resource → searched the QA title → selected it.
3. Deleted that resource with SQL (another admin removing it).
4. Clicked **Save changes**. Results:
   - Real server `PATCH` → **400** `{"message":"Selected resource no longer exists or is not approved. Choose another resource.", "error":"validation_failed"}`.
   - Inline `role=alert` with the same text. The dialog stays open, the typed title and description are kept, and the stale resource chip is still shown.
   - Step rows unchanged: `rowsUnchanged: true`.
5. Recovery: cleared the resource → Save → 200, dialog closes, row saved with `resource_id=null` and the typed title.

Screenshots (opened and viewed): `screenshots/B06-stale-resource-inline-error-desktop.png`, `B06-stale-resource-inline-error-390.png`.

During this proof the 390px capture showed the selected-resource chip pushing the **Change** button off-screen. This was fixed in the same pass: the chip's text is now a shrinkable truncating span and the row wraps. The 390px screenshot shown was re-captured after the fix.
