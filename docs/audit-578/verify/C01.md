# C01 — Edit-review diff must equal the data approval applies

**Status: FIXED — proven on DEV, 2026-10-09 (run `__qa_test_plan_582_1791561997330`)**

## Before
Per the audit: `POST /api/resources/:id/edits` accepted independent `proposedChanges` (shown to moderators in
PendingEdits) and `proposedData` (applied by `AuditRepository.approveResourceEdit`). A request could show a harmless
title change while carrying a different URL in `proposedData`. Dedup fingerprinted only `proposedChanges`.

## Fix
- `server/routes/domains/catalog-contributions.ts`: `proposedData` is the only authority. The server derives the
  canonical old→new diff from it against the stored resource. `proposedChanges` is optional and accepted only when it is
  exactly that derived diff; otherwise it returns 400 naming the field. Dedup fingerprints the canonical diff.
- `server/repositories/AuditRepository.ts`: approval refuses rows whose stored diff and value map disagree, or whose
  values cannot be applied verbatim, with 409 "This legacy suggestion has inconsistent review data. Please resubmit it."
  It applies the reviewed values verbatim (no re-normalization, truncation or path splitting).
- `client/src/components/ui/suggest-edit-dialog.tsx` sends only `{ proposedData }`.
- `client/src/components/admin/PendingEdits.tsx` renders the stored canonical diff.
