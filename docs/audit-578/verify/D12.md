# D12: Bulk approval and admin publishing bypassed the description gate (VERIFIED)

**Environment.** DEV app (`npm run dev`, workflow "Start application", http://127.0.0.1:5000), restarted after the last server edit on 2026-10-09. Admin calls use the `X-Admin-Audit-Key` header (value comes from the ADMIN_PASSWORD secret, never logged) plus an `Origin` header. Harness sources: `evidence-583/harness/` (`lib.mjs` wraps fetch and psql and records every request, status, response excerpt and SQL result). Fixtures all start with `__qa_test_plan_583_`, are deleted by exact id, and each run ends with this residue query:

```sql
select (select count(*) from resources where title like '__qa_test_plan_583_%' or url like '%__qa_test_plan_583_%') as resources,
       (select count(*) from categories where name like '__qa_test_plan_583_%') as categories,
       (select count(*) from subcategories where name like '__qa_test_plan_583_%') as subcategories,
       (select count(*) from sub_subcategories where name like '__qa_test_plan_583_%') as sub_subcategories,
       (select count(*) from resource_edits e where not exists (select 1 from resources r where r.id = e.resource_id)) as orphan_edits;
```

## Before
Audit evidence3.json: three QA resources with empty descriptions. The bulk-approved one and the directly-created approved one kept length 0. The individually approved one got a 97-char fallback.

## Fix
- Every path that makes a resource approved goes through `transitionResourceInTransaction` (single approve, bulk approve, admin create with status approved, editor PUT status). On a transition **to** approved it applies `ensureMinDescription`, the single minimum-description policy.
- Repeated approvals of an already-approved row return 409 (row lock plus expectedStatus) before any content write.
- Later admin edits of a published row keep the admin's validated text (10+ visible chars) as an intentional override. **Blanking** a published description re-applies the fallback, so a public row never has an empty description.

- md5 of all four descriptions is identical before and after the repeats, so content was not mutated
- PUT "Admin override." on the published row returns 200 and the text is kept; PUT "" returns 200 and the fallback is re-applied (len 89)
