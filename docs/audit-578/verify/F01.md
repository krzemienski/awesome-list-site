# F01 — Clear & Re-seed is atomic (source failure or mid-run failure leaves catalog and edits intact)

Status: **FIXED + PROVEN** (scratch DB, browser desktop + mobile, dark theme)

## Before
`server/seed.ts` deleted `resource_edits`, then `resources`, outside a transaction, and only afterwards downloaded the S3 source.
A source failure therefore happened after destructive clearing, and the `research_discoveries.created_resource_id` FK (NO ACTION) made the
resource delete throw after edits had already been deleted (audit OPS-01, source trace; the original was never executed because it destroys data).

## Fix
- Source is downloaded and fully validated before anything is touched (`SeedAbortedError` → HTTP 422 "…; database unchanged").
- Clear + insert run inside one transaction; any insert error rolls everything back ("Reseed rolled back, database unchanged: …").
- Resources referenced by edits, discoveries or user data are preserved (not deleted, not re-pointed) and counted in the result.
- `/admin/database` renders a persistent result panel (`seed-result-failed` / `seed-result-success`).
