## What Publish actually runs
`.replit` → `[deployment] build = ["bash", "scripts/pre-publish-gate.sh", "--publish"]`. In `--publish` mode the gate runs these steps in order, and the first failure exits 1. Replit aborts the promotion when the build command fails.

1. `npx tsc`
2. `check-migration-drift.ts --journal-only` (file checks, no DB)
3. print/responsive browser audits: **skipped**
4. `validate:product-profiles`
5. `validate:standalone-palette-drift`
6. `npm run build`
7. `bundle:budget`
8. image trim, only when the production-only `REPLIT_PUBLISH_IMAGE_TRIM` / `REPLIT_DEPLOYMENT` marker is present

**Why the browser audits are skipped in the build.** No app is serving in the build container, and that container carries **production** env (DATABASE_URL = prod). Booting a server there would connect to prod *before* Publish applies the dev→prod schema diff, so boot breaks on any new column, and a mid-build admin login would write to prod. The two audits therefore run as the `print-audit` / `responsive-audit` DEV workflows against the same source revision; see "Matching DEV browser proof" below.

## The real blocker (found by this proof)
- **Bisect** (`v22-bisect.sh`, `git archive <rev>` + vite build + budget per revision):
  - `572e6739` (the revision production serves) has initial raw **604.6 KiB** (PASS).
  - `681e170d` ("Git commit prior to merge", the 10-09 parallel workers' snapshot) and every later commit up to HEAD sit at **677–680 KiB** (FAIL).
- **Root cause:** that snapshot made `client/src/App.tsx` import `discoveryRedirect` from `shared/discovery-params.ts`. That module imported its facet constants from `shared/resourceFacets.ts`, which pulls in **zod** (~70 KiB raw) for its server-side schemas. The file's own header says browser code must use `resourceFacets-core`. zod therefore landed in the initial bundle.
- None of the per-task gates run `bundle:budget`; only the publish gate does. **The next Publish of main would have failed.**
- **Fix:**
  - `shared/discovery-params.ts` now imports from `./resourceFacets-core`. Its exports are identical; core is zod-free.
  - `scripts/validation/bundle-budgets.json` adds `"(^|/)zod/"` to `initialForbiddenModulePatterns`, so a recurrence fails with a named isolation violation instead of a vague size overrun.
- **After:** initial raw 612.5 KiB, gzip 191.6, brotli 160.8, with 268 modules (was 287). Budget PASS.
- **Mutation proof of the new pattern:** the unfixed HEAD build checked with the new config prints `initial isolation violation: …/node_modules/zod/v4/core/parse.js matches /(^|\/)zod\//` (`5-HEAD-build-budget-with-zod-pattern.out`).
