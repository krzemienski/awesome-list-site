# J13 — Validator checks wrapped resource but not recommendation fields

**Status: PROVEN (2026-10-09). Paid AI: 0 calls.**

## Fix
- `server/contracts/endpointSchemas.ts`: the recommendation item schema now describes every field of `RecommendationResult` and is `.strict()` (no more `.passthrough()`):
  - `confidence`: integer 0–100;
  - `reason`: non-empty string;
  - `type`: one of `ai_powered`, `rule_based`, `hybrid`;
  - `score`: optional, 0–1;
  - `aiGenerated`: optional;
  - `explanation`: `{summary, signals[{code ∈ RECOMMENDATION_SIGNAL_CODES, label, evidence?}]}`, strict;
  - `feedback`: one of `RECOMMENDATION_FEEDBACK_VALUES`, or null;
  - `personalized`: boolean.
- `shared/recommendations.ts`: the signal codes are now one runtime `as const` list. The type is derived from it, so the client type, the runtime validator and the OpenAPI enum share one source.
- `docs/api/openapi.yaml` was regenerated with `npx tsx scripts/export-openapi-yaml.ts`. **Disclosure:** the committed yaml was already stale from other tasks' contract edits (`j13-openapi-stale.log` shows the drift before this item's change). The regeneration therefore also absorbed those sections. The diff is the generator's deterministic output; nothing was edited by hand.

## Before
