# H09 — Theme account-sync failures are silently swallowed

**Status: FIXED and proven on DEV with a real signed-in throwaway user (2026-10-09).**

## Before
- `AccountThemePreferenceBridge` applied the choice locally, queued a PUT, caught any failure and only refetched.
- Once a local selection was made, the hydration effect refused account truth.
- The user saw an apparent success either way.

## Fix
`client/src/components/ui/theme-provider.tsx` and `ThemeSettings.tsx`:
- The bridge exposes a syncing/saved/failed/conflict status.
- `/settings/theme` shows an inline alert ("…saved only on this device") with a "Retry account save" button.
- **Addition in this pass:** a destructive toast, "Theme not saved to your account", with a Retry action, raised from the bridge. Without it the failure was invisible when the pickers were scrolled away from the inline alert, or on the design-system showcase picker. The toast is dismissed on a successful save.
- On 409 the bridge refetches the latest revision. Retry re-sends the local choice against that revision (409, then 200). The device keeps the user's selection until the save succeeds.

## Recipe executed
Script: `evidence-587/h09.mjs` → `h09-out.txt`. The user is a Clerk throwaway, `__qa_test_plan_h09_…`, minted through the Clerk backend and signed in with a sign-in token ticket.

Desktop (editorial → brutalist) and 390px (brutalist → editorial):
1. Block `PUT /api/user/preferences` in the browser and pick another system. The inline alert reads "Couldn't save to your account. This selection is saved only on this device." with "Retry account save". The toast is visible in the viewport. The server value is unchanged (`null` / previous).
2. Unblock and click Retry. The status reads "Theme saved to your account.", the toast is gone, and the server is `{"systemId":"brutalist","accentId":"amber"}`.
3. Real conflict: another device writes through the API (200, revision bumped), then the user picks an accent with the page scrolled (scrollY 127 / 1264). The PUT returns 409, the alert reads "Your account changed elsewhere…", and the toast is visible. The toast's Retry gives 409 then 200, and the server matches the user's choice.
4. A fresh browser context signed in as the same user loads the saved choice (`applied=brutalist/magenta` and `editorial/orange`, as expected).
5. Teardown: the Clerk user was deleted first, then the local row. Residue `{"users":0,"prefs":0}`.
