# F10 — Admins can cancel a running link-health scan

Status: **FIXED + PROVEN** (scratch DB, background jobs on, browser desktop + mobile)

## Before
`cancelJob` existed but had no route; no running-scan Cancel control; link checks had no abort signal (audit OPS-07).

## Fix
`DELETE /api/admin/link-health/jobs/:id` (admin, CSRF origin check) aborts an AbortController threaded through both link-check passes;
finalization only applies while the job is still processing; dashboard has "Cancel running scan" with a confirmation.

## Steps / evidence
30 slow fixtures (`__qa_test_plan_lh_slow1..30` → a local server that answers after 14 s) + 10 normal = 40 links.
1. Desktop: started scan #5 ("0 of 40"), clicked Cancel running scan → confirm → `DELETE` 200 at 16:18:30.819, status cancelled, "Cancelled by administrator".
   Slow-server log: all 10 in-flight requests `ABORTED-by-client` at 16:18:30.812–.814 (open = 0).
2. Banner "Scan #5 was cancelled … Counts … from previous completed scan (#4 …)", Healthy 2 / Broken 8 still shown.
3. Run scan again → `POST` 200 job 6 at 16:18:31.245 (new requests at 31.256) — no waiting for the cancelled pass.
4. Mobile: same with jobs 7/8. A second DELETE on finished job 6 → 409 "Job 6 already finished (cancelled)".
5. 25 s later: jobs 5–8 still cancelled (no late overwrite); checks table still only job 4 (10 rows); broken-links API 8; slow server saw 40 requests total (first batch of each job only).
