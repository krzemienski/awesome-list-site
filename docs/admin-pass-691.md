# Admin panel hands-on pass

Every admin section was driven in a real browser while signed in as a disposable admin.
All checks ran against dev data and `__qa_test_691` records, which were removed afterwards.
"Checked" lists the controls that were used. "Fixed" lists what changed.

| Section | Checked | Fixed |
|---|---|---|
| Overview | Four stat cards and their links into each tab; recent activity; enrichment and link-check summaries. Resources (1,819 approved) matches the Resources tab's default Approved filter. Subcategories (92) matches the Subcategories tab. Pending approvals matches the Approvals queue (both read the server's pending total). | A cancelled enrichment run now shows a warning, "cancelled before finishing", not a success. The Subcategories card had test ids copied from an old Journeys card; it now uses its own ids. |
| Approvals | Single approve and reject, bulk reject, rejection-reason helper, selection. | Toasts name the resource title. Bulk toasts list up to 3 titles, then "and N more". The reason box shows "Too short — add N more characters". QA and test-domain submissions show a "Test entry" badge. Public submissions that use reserved test domains are refused in production with a field error on the URL (drafted task #214). |
| Edits | Approve and reject a suggested edit. | Toasts name the edit number and the resource. |
| Enrichment | Job list, status chips, job details. | None. Job #8 shows "failed" with 78/78 processed. That record is accurate: the run was orphaned by a server restart. |
| Researcher | Launch validation, job history, job details dialog. | Launch-validation errors now appear inline next to the launch buttons instead of as toasts. The job dialog title showed "Research Job #" with no number while the details loaded; it now always shows the number. |
| Export | Markdown, JSON, CSV and OPML downloads; validation panel; link-check block; full database backup. | Success toasts name the saved file. Download failures explain what went wrong. The validation toast reports how many problems were found. The empty validation panel points to the "Run Validation" button. The scan figures are labelled "At scan time", with a note on how they relate to Link Health (drafted task #632). The backup toast names the backup id. |
| Database | Table stats, migrations, seeding control (not run). | None needed. |
| Resources | Search, status filter, Sort dropdown, pagination (page 2 of 80 and back), and the edit dialog: reject and then approve again. | Rejecting from the editor now requires a reason of at least 10 characters, shown inline in the dialog and enforced by the server (drafted task #596). The success toast names the resource and says the contributor will see the reason. Column headers are not sortable; sorting uses the Sort dropdown, as the header gives no sort affordance. |
| Categories / Subcategories / Sub-Subcats | Create, rename and delete across all three levels; empty-name validation (shown inline in the dialog). | Toasts name the item. |
| Users | Search, sort headers, email reveal and mask, role change in both directions, delete. | Toasts name the user (their name or masked email). The delete confirmation now names the user as well as the masked email. |
| GitHub | Repository card, recent sync rows, Logs dialogs, Sync Status card, invalid-repository validation, Reset. | Drafted task #164: a failed export is now shown as "completed, commit landed" only when that run's own commit reached GitHub. Exports now record their queue id on their history row, and keep their commit SHA on the queue row even when the steps after the commit fail. Older rows without these are matched only when exactly one export was running at the time. The earlier 10-minute matching window picked up a later run's commit, which hid blocked export Job #47 from history. Both cases were checked with disposable sync rows: a sequential export and a second export queued while the first was running. The Logs dialog now names the repository each run targeted. |
| Digests | Queue health, Refresh, and which section the Settings trigger says is open. | The Settings trigger shows "· Digests", "· Journeys" and "· Sub-Subcats", and the open item is marked "(open)" (drafted task #610). The header "New entry" button now states that it adds a resource. |
| Link Health | Stat cards, count-source caption, problem-list filter, member reports filter. | The caption explains that the cards count the latest scan's flagged resources that are still in the catalog, against what the scan recorded when it finished (drafted task #632). |
| Audit | Resource ID filter including invalid input, rows per page, Previous and Next, detail dialog, Refresh, contact inbox. | Actions read as words ("user role changed"), as in the reference. Refresh now shows "Updated <time>". The layout matches the reference: ID, Actor, Action, Target, Status and When columns with mono cells and status chips. Two differences are intentional: actor text stays neutral to keep the accent colour for the primary action, and the subtitle gives the real page size (drafted task #618). |
| Journeys | Step add, edit, delete and reorder on a QA step. | Toasts name the step. A blank title shows "A title is required before you can add this step" in the dialog instead of only disabling the button. |
| Research | Brief cards and brief details. | None needed. |

Notes
- Toasts close after about 5 seconds. A few "no toast" observations (single approve, category create, step add) came from captures taken after the item had already updated. The same code paths showed their toasts on other runs.
- Creating a database backup does not ask for confirmation. This is intentional: a backup only adds a new copy and changes no existing data.
