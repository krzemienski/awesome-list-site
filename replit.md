# Awesome Video Resource Viewer

## Overview

A production-ready React application for browsing and discovering over 4,000 curated video development resources. The project uses PostgreSQL as the single source of truth for all data, providing a modern, mobile-optimized user interface with advanced search and filtering capabilities, dark theme support, and Google Analytics tracking. Features include AI-powered learning platform capabilities, user authentication, admin panel, and bidirectional GitHub synchronization for `awesome-list` repositories. The business vision is to create a leading platform for video development education and resource discovery, leveraging AI for personalized learning paths and an engaged community.


### HTTP delivery cache contract (August 19, 2026)
- **HTML is always `no-store` and has no validators** (GET and HEAD): each document carries a unique CSP nonce, so a cached body paired with a fresh header would block its inline bootstrap scripts.
- **Hashed `/assets/*` are `public, max-age=31536000, immutable`**; filenames are content-addressed. A first-response `private` header seen at the platform edge is the Google Frontend/GAESA session-affinity `Set-Cookie` rewrite, not origin policy; cookie-carrying requests preserve the public origin header.
- **Catalog/taxonomy reads** (`/api/awesome-list`, known taxonomy-filter variants, nav, category/tag trees) use `public, max-age=60, must-revalidate` plus ETags. Unknown filter slugs retain `max-age=0` so they cannot create unbounded server-cache keys.
- **Anonymous `/api/public/*` successful reads** use `public, max-age=60` and ETag revalidation; resource 404s are `no-store` so an approval can become visible immediately. Authenticated responses remain non-public.

**Production status**: see `reports/prod-ops-2026-11-06/PLAN.md` (ground truth and open defects B1-B14) for the current state.

## Taxonomy listing API

- `GET /api/awesome-list/listing?level=category|subcategory|sub-subcategory&slug=<slug>&page=<n>` returns one deterministic 24-resource taxonomy page, totals, child counts, tags, and parent metadata. It slices the same cached tree and tree order as crawler prerendering; default category browsing must use this endpoint rather than `/api/awesome-list`.

### Production audit cycles 20–21: deploy pitfalls (November 5, 2026)
- Each publish adds an empty "Published your App" commit (author Replit Agent) on top of the workspace HEAD, so the next sync is never a fast-forward. Confirm `git rev-parse <commit>^{tree} <commit>^^{tree}` prints one tree twice, then `git reset --keep origin/main` in the workspace. Never publish on top of it.
- Production can drift ahead of GitHub when a publish is made from workspace-only commits. Before a sync, list `origin/main..HEAD` in the workspace and keep a backup branch of anything that is not an empty publish commit.
- Config lives in Replit. Credentials and `VITE_GA_MEASUREMENT_ID` are in Secrets, and public config (`VITE_SITE_*`, `VITE_DEFAULT_THEME`, analytics tokens) is in `.replit` `[userenv.*]`. The workspace `.env` (gitignored, but shipped with the publish and loaded by `dotenv` in `server/index.ts:1` and `vite.config.ts:2`) is only a mirror of those values. Values Replit sets win over `.env`, which is how `.env` once drifted: it held an old GA ID and the GitHub Pages URL while the site ran on Replit's. Change a value in Replit first, then copy it into `.env`. `.env.local` (unused dev-server keys) was retired in C22.
- The site turns off ALL analytics when `navigator.webdriver` is true (`client/src/lib/analytics-suppression.ts`, by design). Every automated browser sets it, so a consent or analytics check sees zero vendor requests whatever the code does. Add the initScript `Object.defineProperty(Navigator.prototype,'webdriver',{get:()=>false,configurable:true})` before judging analytics behaviour.
- Withdrawing analytics consent must also drop requests that are already queued: PostHog batches every 3 s and its replay buffer every 2 s, and Amplitude flushes every 1 s and enriches events in a setTimeout. `request_batching: false`, `flushIntervalMillis: 0`, discarding the replay buffer on opt-out, and a consent check in the Amplitude enrichment plugin close this (#242, #244).
- Keyboard checks through chrome-devtools `press_key` release the key at once. Radix radio groups select on arrow keys only while the key is still held (the item's onFocus clicks while an arrow-key flag is set, and roving focus moves in a `setTimeout`). A "focus moves but nothing is selected" result needs a held-key retry before it counts as a FAIL.
- Several agents driving one chrome-devtools browser collide. Give each lane its own `isolatedContext`, re-select its page by id before every action, and never touch another lane's page.
- Too many teammate panes fail new spawns with "fork failed: Device not configured". Stop finished teammates before spawning more.

The Awesome.Video DS contract documented in `docs/` + `HANDOFF.md` is implemented with five intentional, in-repo divergences from the canonical handoff. Every future Stage-5/Stage-6 DS sweep should treat these as architectural decisions, not per-occurrence violations:

1. **shadcn/ui primitives replace raw `.btn / .card / .chip / .input`.** The runtime surfaces use `Button`, `Card`, `Badge`, `Input` (and other shadcn primitives) styled through the `client/src/index.css @theme inline` bridge that maps `--color-*` shadcn tokens onto DS tokens (`--accent`, `--bg`, `--surface`, etc.). Searching the DOM for stray `<button>` outside `.btn/.tab/.icon-btn` is expected to return many — that is shadcn working as designed. Class-compliance audits (DS Stage 6) should compare against the shadcn-bridge surface, not the raw handoff classes.
2. **Body-level atmosphere + `.page contents` wrapper.** The `--bg-atmosphere` gradient is painted on `body` (handoff parity), and `MainLayout` wraps the chrome subtree in `<div className="page contents">` so the DS structural-class contract is satisfied without disturbing the `SidebarProvider` flex layout. The `contents` utility suppresses `.page`'s own box, so its container visuals (`position: relative`, min-height, background) are inert — atmosphere continues to come from body-level rules. If a future DS pass needs `.page` container visuals to take effect, drop the `contents` utility and re-verify the flex/peer chain.
3. **2-system × 10-accent runtime switcher (May 23, 2026; narrowed to Editorial + Geist on Oct 12, 2026).** The two system skins (Editorial — default — and Geist) are live and switchable at runtime via the picker at `/settings/theme`. Token application is CSS-attribute-driven: per-system token blocks live as `:root[data-system="..."]` selectors in `design-system.css`, and per-accent overrides live as `:root[data-accent="..."]` blocks. `applyDesignSystem(systemId, accentId)` (in `client/src/lib/design-system.ts`) only toggles the two attributes on `<html>` + persists to `localStorage` (keys `ds-system`, `ds-accent`) — no inline style writes. The `client/index.html` boot script reads both keys pre-paint and applies them before any module runs, so personality swap is FOUC-free. Default: Editorial + Crimson. Accent default per system follows the handoff's `SYSTEM_DEFAULT_ACCENT` map (editorial→crimson, geist→cyan) — if the user is on a system's natural default and switches systems, the accent nudges to the new system's natural default; otherwise the explicit accent choice carries across.
4. **Shell chrome restructure (July 24, 2026).** The reference DS shell (full-width 60px `.header` owning the brand, `.sidebar`/`.icon-rail` starting below it at `top: 60px`) is implemented via the shadcn sidebar: `SidebarProvider` is a flex column with `--header-height: 60px`; `AppHeader` renders full-width first (brand cluster = BrandMark tile 28px + `AWESOME.VIDEO` mono wordmark, hidden below `lg`), and the sidebar's gap spacer + fixed panel are offset with `top-[var(--header-height,0px)]` / `h-[calc(100svh-var(--header-height,0px))]` in `components/ui/sidebar.tsx`. ## System Architecture

The application employs a client-server architecture. The frontend is a React-based single-page application built with Vite, utilizing `shadcn/ui` components, Tailwind CSS, and React Query for data fetching. The backend is an Express.js server providing RESTful API endpoints. Data is stored in a PostgreSQL database using Drizzle ORM, with a defined schema for resources, categories, and subcategories.

### UI/UX Decisions
- **Editorial + Crimson** is the default design system; Geist is selectable; 10 accents; fonts come from the design-system tokens (`--font-body`); 12px radius scale (`--radius: 12px` in `client/public/ds/design-system.css`). See "Design-system verification scope" above.
- Mobile-optimized responsive design with WCAG AAA compliant 44x44px touch targets and a collapsible hierarchical sidebar.

### Technical Implementations
- **Frontend**: React 18+ with TypeScript, Vite, Tailwind CSS, `shadcn/ui`, React Query for state management, Wouter for routing.
- **Backend**: Express.js, Drizzle ORM, Node Fetch for external data, Remark for Markdown parsing.
- **Data Architecture**: PostgreSQL database serves as single source of truth. `getAwesomeListFromDatabase()` method builds complete hierarchical structure from database tables (categories → subcategories → sub-subcategories with LEFT JOINs). Supports 3-level hierarchy with accurate resource counts at each level.
- **Sidebar Layout**: shadcn sidebar with a gap-spacer + fixed panel (July 24, 2026 shell restructure). The full-width 60px `AppHeader` owns the brand; the sidebar/rail starts below it via `--header-height` (set on `SidebarProvider` in `MainLayout.tsx`). Expanded width 17.5rem (280px), collapsed rail 3.5rem (56px).
- **Deployment**: Configured for deployment on Replit, with optimized production builds. Production is already seeded (4,000+ live resources). Never run Seed or Clear & Re-seed there without the owner's explicit approval.

### Feature Specifications
- **Search & Discovery**: ⌘K command palette (`cmdk`) over server search `/api/search`.
- **AI Recommendations**: Personalized resource recommendations based on user profiles, skill levels, and learning goals (live: `/api/recommendations`).
- **Authentication System**: Clerk (Replit-managed white-label tenant, migrated August 2026 from Replit Auth + local email/password; 14 users migrated with emails/passwords preserved). Sessions are Clerk `__session` cookies verified by `clerkMiddleware` (server/index.ts); Clerk's Frontend API is same-origin proxied at `/api/__clerk` (server/middleware/clerkProxyMiddleware.ts). ID bridge: `users.id` = legacy subject = Clerk `externalId` (`sessionClaims.userId`); Clerk-native `user_...` ids are used ONLY for Clerk API calls. `clerkUserContext` (server/clerkAuth.ts) resolves `req.dbUser` per request and JIT-provisions first-time Clerk users (identity columns email/name/avatar are snapshotted once at insert; Clerk owns them afterwards). Protected endpoints use `requireAuth`; sign-in/sign-up pages are `/sign-in` + `/sign-up` (legacy /login, /register, /forgot-password, /reset-password 301-redirect). Passwords, resets, and multi-device session management live in Clerk (Profile "Manage account security" opens the themed Clerk portal). The `sessions` table remains (legacy, unused by auth).
- **GitHub Integration**: Implemented GitHub import system for fetching raw resource URLs from public repositories, and an export system leveraging Replit GitHub OAuth to commit `awesome-lint` compliant markdown directly to GitHub.
- **Batch Enrichment System**: Claude AI integration for automated metadata extraction from resources. Features include sequential processing with configurable batch sizes, rate limiting, smart URL validation, retry logic, accurate tracking, and a dedicated admin UI for monitoring and control. Integrated web scraping extracts page metadata (title, description, Open Graph images, Twitter Cards, favicon) using Cheerio with proper error handling for missing meta tags.
- **Guest Bookmarks (Task #329)**: Signed-out visitors can save resources to an on-device store (`client/src/lib/guestBookmarks.ts`, localStorage `guest-bookmarks-v1`, cap 50, in-memory fallback when storage is unavailable). `/bookmarks` routes through `BookmarksGate`: authed → full library, guest with saves → `GuestBookmarks` page with a "sign in to keep these everywhere" prompt, save-less guest → classic AuthGuard redirect. `GuestBookmarkMerge` (mounted in App) pushes guest saves through the existing authed bookmark API after sign-in — pre-dedupes against GET /api/bookmarks (the POST upsert would clobber notes), drops saves whose resource 404s, clears local entries only on confirmed success, and toasts the outcome. Funnel events: `guest_bookmark_added/removed`, `auth_prompt_shown` (context enum), `bookmarks_merged` (see docs/ANALYTICS.md, docs/MIXPANEL.md). Guests get plain saves only — notes/statuses/collections/journeys stay account features.
